## The problem

WI-024's brief — `prototypes/briefs/02-material.md` — publishes the amber
collision as **ten lines across six files**, and says in its own words:

> **Measured at `d343300`**

At `d343300` the tree does hold amber on exactly ten lines in exactly those
six files. **The brief is a true historical record.**

The pin that carries it, `apps/web/src/__tests__/forge-briefs.test.ts`, does
not assert that history. It asserts the **live working tree** still holds amber
at each cited line:

```
AssertionError: AppShell.tsx:37 no longer holds amber: expected
' * hollow ring read the same in a scr…' to contain 'amber-'
```

And WI-071's accent work — now salvaged onto `wi/087-accent-salvage` — does
exactly what that brief's own **"Under Forge"** column prescribes: it takes the
amber off eight of the ten sites and splits the ninth. `docs/panel-accent.md`
is the new inventory.

So the pin asserts a rule the brief has already superseded. The pin landed on
`main` **after** WI-071 forked, which is why WI-071 was green on its own
branch and the collision only exists now.

**This is the one red gate on the accent salvage.** `npm run test` is 448 of
449, and the single failure is this assertion. It blocks the Forge accent
direction from landing.

## The second red, in the same file

`forge-briefs.test.ts:275` holds a hard-coded phrase:

```ts
const exception = 'one declared exception, the Needs-you rail';
```

The boundary rule gained a **second** declared crossing, and
`prototypes/DIRECTION.md` — repaired in `d3ef0d2` — no longer contains that
phrase. Two cases are red on that too.

The pin's own comment says what it is for:

> The load-bearing phrase. The flat rule — the one without this clause — is what
> two of the briefs quoted before the lead settled the landing page's premise,
> **and it is the one thing a document quoting itself cannot catch.**

So the pin's purpose is: **the briefs must quote the rule's exception clause,
whatever the document's exception clause currently says.** The hard-coded
string was a proxy for "the exception clause", and the proxy is what broke.
**The fix is not to swap one phrase for another** — it is to make the pin read
the rule out of the document and hold the briefs to that, and to make it
stronger while you are there.

## Why neither is fixed by re-anchoring, and what to do instead

The rest of `forge-briefs.test.ts` anchors its assertions to a measured commit
and guards them with `skipIf(!measuredCommitReachable)`. **Re-anchoring the
amber one to `d343300` would make the check stop running in CI entirely** — CI
checks out at depth 1, so the measured commit is not reachable and the test
skips. That is a weakened gate, not a fixed one.

The fix is to **re-state each pin as what the rule now says**, keeping the
live-tree assertion and making it stronger than the one it replaces:

- The ten sites the brief names are the sites the accent rule claims, and the
  accent system must not reintroduce amber at any of them.
  `docs/panel-accent.md` is the current inventory.
- The briefs must quote the rule's exception clause, read out of the document
  rather than hard-coded — so the next time the rule gains or loses a crossing,
  the pin follows the rule instead of breaking.
