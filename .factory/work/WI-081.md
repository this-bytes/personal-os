## The problem

**The contract publishes a number, the code enforces a number, and nothing
checks that they are the same number.**

| Where                                            | What it says                                                      |
| ------------------------------------------------ | ----------------------------------------------------------------- |
| `CONTRACTS.md:165` — the published shape         | `note?: string; // up to 2,000 characters, the owner's own words` |
| `apps/server/src/api/executions.ts:9` — the code | `note: z.string().max(2_000).optional()`                          |

**Both are right today. Nothing would say so if one of them changed.** The
contract could publish `2,000` while the code caps at `20_000`, or the contract
could drop the bound entirely, and the build would stay green — because **no
test reads this field.**

**Measured, not described.** Probe read `apps/server/src/__tests__/published-shapes.test.ts`
in WI-078's verification and found exactly three cases: the template record's
published kinds, the routes that write no audit entry, and the counts of routes
and audit entries. **There is not one reference to `note`, to
`ResolveExecutionInput` or to `2_000` in the file.** The lead re-read the test
and confirmed it. **It passes identically with the bound unpublished, with it
mis-numbered, or with it wrong.** A gate that passes on a wrong tree is not a
gate.

**And the file's own header says it holds two claims, while it holds three.**
The doc comment at `apps/server/src/__tests__/published-shapes.test.ts:7-23`
reads **"The two published shapes"** and lists two bullets — the template
record's kinds, and the measures route's audit entries. The `describe` block
below it holds **three** `it` cases, because the third (the counts) was added
after the header was written. **The header is a record, and it is stale.**

**Why this is an item and not a shrug.** This factory has spent the evening
repairing the same class four times: **WI-028** — pointers into the contract
that no longer point; **WI-062** — citations whose line numbers had moved;
**WI-066** — a published field count that disagreed with the code's; **WI-079**
— a published citation that resolves to nothing. **Each was found by reading,
after the fact, and each cost a verification to find.** This is the first one
where the factory can close the class instead of finding the next instance —
**one case in a test that already exists, in the house pattern, reading both
sides.**
