# WI-133 — The dependency audit job audits twice, and the second audit is the one that times out

**Owner:** the session that measured it
**Verifier:** Chief — this one is a measurement, and it is checked by re-running it.
**State:** implement — the number is claimed and published; the work is one word.

**Numbered:** 2026-10-22 — **WI-133**, read immediately before it was taken: `main`'s
published number block read **"Next free number WI-133"**, and WI-133 appeared in no
item file, no dispatch record, no commit and no branch name. **This claim is published
as its own commit, before the branch carries the change** — the claim-first protocol
the factory settled on after three number collisions in three hours.

## The finding

**The `Dependency audit` job is the only job in the pipeline whose install audits, and
it then audits again.** `npm ci` runs its own post-install audit against the registry
unless `--no-audit` is passed. The job's install line omits it, and the job's next step
runs `npm audit --audit-level=high`. **So the job pays for the registry round-trip
twice, and its three siblings pay for it not at all:**

| Job                                     | install line                                   | timeout |
| --------------------------------------- | ---------------------------------------------- | ------- |
| **Dependency audit**                    | `npm ci --ignore-scripts`                      | **10**  |
| The published contract matches the tree | `npm ci --ignore-scripts --no-audit --no-fund` | 10      |
| The contract's pointers point at code   | `npm ci --ignore-scripts --no-audit --no-fund` | 10      |
| Build and run the stack                 | `npm ci --ignore-scripts --no-audit --no-fund` | 30      |
| Build and test                          | `npm ci`                                       | 30      |

## The measurement, which is the whole point

**The job did not wait for a runner. It ran out of its own budget, and the numbers
say where the budget went.** Measured on the check-runs of `ccc3564`:

| Job                                     | started  | completed | duration    | conclusion    |
| --------------------------------------- | -------- | --------- | ----------- | ------------- |
| **Dependency audit**                    | 03:01:34 | 03:11:49  | **10.25 m** | **cancelled** |
| The published contract matches the tree | 03:01:34 | 03:01:48  | **0.23 m**  | success       |
| The contract's pointers point at code   | 03:01:34 | 03:01:50  | **0.27 m**  | success       |
| Lint the workflows                      | 03:01:34 | 03:01:39  | 0.08 m      | success       |
| Build and test                          | 03:01:34 | 03:12:03  | 10.48 m     | success       |
| Build and run the stack                 | 03:12:05 | 03:13:17  | 1.20 m      | success       |

**Every job started at 03:01:34 — the queue wait was zero.** The audit job's own
duration is **10.25 minutes**, and its budget was 10: that is a timeout, and GitHub
reports a timeout as `cancelled`, which is the same verdict a superseded run carries.
**A timeout and a cancellation are indistinguishable from the conclusion alone**, so a
required check that accepts only `success` reads this run as a failure and the badge
says "CI - failing" for a tree that was never at fault.

**And the two sibling jobs did the same install inside the same budget in fifteen
seconds.** `npm ci --ignore-scripts --no-audit --no-fund` costs **0.23 and 0.27
minutes** — checkout, setup-node, the install and the rest of the job together. **The
install is not the cost. The audit is.** One explicit `npm audit --audit-level=high`
against this repository's lockfile takes **one second**.

So the 10.25 minutes were the audit work, and roughly half of it was work this job
did not need to do: the implicit audit inside its own install.

## What this item does

**One word, in one line of one job.**

```diff
       - name: Install dependencies
-        run: npm ci --ignore-scripts
+        run: npm ci --ignore-scripts --no-audit --no-fund
```

**The job then audits exactly once, with the level the job names**, and its install
line becomes byte-identical to its three siblings'. The job's cost becomes the
siblings' cost — about fifteen seconds of install — plus one explicit audit.

## What this item does not do

- **It does not weaken the gate.** The explicit `npm audit --audit-level=high` step
  still runs and still fails the job on a high-severity finding. Nothing about what
  the job forbids changes; only the duplicated round-trip is removed.
- **It does not delete the install.** The audit's input is the lockfile, not the
  installed tree — `npm audit --audit-level=high` in a directory holding only
  `package-lock.json` and no `node_modules` reports **"found 0 vulnerabilities"** and
  exits 0, and reports the same with the tree present. So the install could go, and
  the job would get faster still. **That is a bigger change in shape to a
  vulnerability gate and it wants the owner's word; this item lands the one-word
  version first and leaves the deletion as a separate decision.**
- **It does not raise the timeout.** A larger budget would leave the flake in place:
  the next slow registry round-trip re-flakes it. The duplication is removed instead
  of hidden.
- **It does not claim that the cache replaces the install.** `actions/setup-node`
  with `cache: npm` caches `~/.npm` — the download cache — and not `node_modules`. It
  makes `npm ci` faster; it does not replace it.
