# WI-001 — Split the web client bundle by route

**Owner:** Cog
**State:** triage
**Dispatched:** 2026-10-20, commit `d4ee699`

## Problem

`npm run build` emits a single JavaScript chunk of 584.55 kB (173.35 kB
gzipped) and Vite warns that chunks above 500 kB are not split:

```
dist/assets/index-D7ouK18I.js   584.55 kB │ gzip: 173.35 kB
(!) Some chunks are larger than 500 kB after minification.
```

All nine page components are imported eagerly in `apps/web/src/App.tsx`
(`Login`, `Conversations`, `ConversationDetail`, `Agents`, `Factory`,
`Resources`, `Automations`, `Settings`). The owner therefore downloads the
agents page, the factory board and the settings screen before the login
screen can paint. The control panel is the first thing a user touches after
starting the instance, and it is the slowest part of starting it.

## Why now

It is the one measurable performance defect in the product, it is entirely
inside Cog's ownership, and it is small enough to land as a single
reviewable change.

## Acceptance criteria

- [ ] No emitted JavaScript chunk exceeds 300 kB.
- [ ] The chunk the browser loads for the first paint is smaller than it is
      today.
- [ ] Every route still renders. A lazily loaded route shows a fallback
      (`apps/web/src/components/ErrorState.tsx` already exports a
      `LoadingState`) rather than a blank page.
- [ ] `npm run build`, `npm run typecheck` and `npm run test` pass.
- [ ] The Playwright suite passes. It navigates to `/agents` and
      `/automations`, which are both lazy routes — a route-splitting bug that
      breaks navigation will fail here.

## Not in scope

- No visual redesign and no change to the look of any page.
- No change to the router's URL structure.
- No change to the API client, the event stream or any server behaviour.
- Do not add a bundler plugin dependency if `React.lazy` or a `manualChunks`
  split will do.

## Gates

- `npm run typecheck`
- `npm run test`
- `npm run build`
- `npm run test:e2e`

## Notes

The routes are in `apps/web/src/App.tsx`. `LoadingState` is in
`apps/web/src/components/ErrorState.tsx`. React Router v7 is in use
(`react-router-dom` 7.18.4). Chunk size is measured from the build output, so
quote the real numbers in the report, not an estimate.

## Outcome

**Accepted.**

The client now ships one chunk per route, with the heavy vendor libraries
split out. Measured from the real build output:

| Chunk            | Before  | After   |
| ---------------- | ------- | ------- |
| Largest chunk    | 584 kB  | 186 kB  |
| First-paint JS   | 584 kB  | 153 kB  |
| CSS              | 36.9 kB | 36.9 kB |

No emitted chunk exceeds the 300 kB limit, which the build now enforces, so a
change that quietly re-bundles the panel into one file fails the build rather
than the user.

Gates at acceptance, run by Chief against the committed tree:

```
npm run typecheck      6 workspaces clean
npm run test           158 tests passed
npm run format:check   clean
npm run build          5 vendor chunks + entry, largest 185.71 kB
npm run test:e2e       3 passed
```

## Note: two workers, one worktree

The work item was opened in the factory group *and* dispatched directly to
Cog. The group post woke Cog as well, so two workers implemented the same
change in the same worktree and overwrote each other. Both reported the
symptom as "something else is modifying this repository".

Chief cancelled the duplicate and kept the implementation that was already
written. The rule that would have prevented it — post to the group *or*
dispatch directly, never both — is now in `FACTORY.md` and
`.factory/chief.md`.

## Note: a fix found along the way

The deployment script needed its own change: the agent it registers was named
"Deploy Echo", and a name with a space is not a resolvable mention, so the
script could never address it. The agent is now "DeployEcho" and the
conversation it creates uses the `mentions` routing mode with the agent as a
participant.

That is a different fix from this work item, so it was committed separately
rather than folded in here.
