## The defect, measured

`CONTRACTS.md:216-217` publishes, of the waiting list's turn:

> **The route is for the run the list draws as a turn.** … the id the list draws
> is `turn:<execution id>` — **the id this route takes**.

**That sentence is false, and a client written to it literally breaks.**

|                          | Measured                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------- |
| What the list draws      | `` `turn:${turn.executionId}` `` — `apps/server/src/api/waiting.ts:126`                                 |
| What the client posts    | the **bare** execution id — `apps/web/src/components/WaitingList.tsx:279` strips `turn:` itself         |
| What the route takes     | the raw `:id` — `apps/server/src/api/executions.ts:21-22`                                               |
| What the server looks up | `eq(executions.id, executionId)` — `apps/server/src/modules/executions/service.ts:71` — **the bare id** |

**So the id the list draws is not the id the route takes.** A client that
follows the published sentence posts `/api/executions/turn:exe_123/resolve` and
gets _"Execution not found"_. **The prefix is the list's own naming, and the
route never carries it.**
