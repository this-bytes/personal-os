# WI-153 — A Hermes ACP preset, and a way to prove a runtime

**Owner:** the contract lane — the session that owns `CONTRACTS.md` while its
slices are in flight.
**Verifier:** Probe, who reviews the slice before it is accepted.
**State:** accepted — a Hermes ACP preset, and a way to prove a runtime. It
landed in `main` at `dcc7fec` and `CONTRACTS.md` publishes it: the catalogue and
the evidence a claim rests on are `packages/contracts/src/adapter-presets.ts`,
the proof is `scripts/verify-runtime.ts`, and the session the protocol asks for
is `packages/agent-adapters/src/acp.ts`. Closed under ADR 0012 on 2026-10-23.
**Branch:** none — the slice landed on `main`.
**Base:** `6d51566`

## Problem

**The catalogue named a runtime nobody here could reach, and nothing in the
repository could show whether any runtime worked at all.**

- `packages/contracts/src/adapter-presets.ts` — the only Hermes preset was
  `hermes-http`, pointed at `https://hermes.example.com`: a gateway URL that
  no installation publishes. The installed Hermes publishes an **ACP**
  surface, and the catalogue had no template for it.
- There was no way to ask a runtime whether it answers. The presets are
  templates; the contract says so, and it was right — nothing here could prove
  a template was more than a template.

## What was found

**Hermes 0.21.0 is installed on this machine**, at
`C:\Users\Aaron\AppData\Local\hermes\bin\hermes.exe`, and it publishes the
Agent Client Protocol: `hermes acp` speaks ACP over stdio. Its handshake
answers `initialize` with `protocolVersion: 1`, `loadSession: true` and a
prompt capability for images.

**Running it found two defects in the product.**

1. `packages/agent-adapters/src/acp.ts` — `session/new` was sent with no
   parameters. The protocol asks for the working directory and the MCP
   servers, and Hermes refuses a request that leaves them out: the turn died
   with `invalid params`. The adapter's own `session/load` already sent both.
2. `packages/agent-adapters/src/jsonrpc.ts` — an error's `data` was dropped,
   so a refusal read as _"Internal error (code -32603)"_. The reason was
   there all along — _"No LLM provider configured. Run `hermes model` to select
   a provider"_ — and the owner never saw it.

**And the turn ran.** With the owner’s approval, Hermes was pointed at the
MiniMax endpoint MiniMax Code already uses. The credential went into Hermes’s
own `.env` and nowhere else: it is not in this repository, not in Personal OS,
and not in the transcript. The endpoint speaks the Anthropic Messages
protocol and authenticates with a bearer token, which is why Hermes needed
`api_mode: anthropic_messages` and the documented inference-endpoint override.

The answer came back through the product’s own adapter:

> I write and test code in this repo — reading files, editing, running
> builds/tests, and using git — plus web search/extraction and browser
> automation when needed.

## What changed

**The catalogue gained `hermes-acp`.** The `hermes` command in ACP mode, the
leader persona, and the honest notes: the credential belongs to Hermes, not
to this panel, and the runtime refuses to open a session without a provider.

**`scripts/verify-runtime.ts` proves a runtime.** It takes a preset, builds
the adapter the worker would build, and asks the runtime two questions
through the product's own code: does it answer the handshake, and does it
answer a turn. It runs a real agent and spends the runtime's tokens, and it
refuses a preset that needs a credential it cannot supply rather than
half-running it.

**The ACP adapter opens a session the way the protocol asks.** The working
directory the connection was configured with, and no MCP servers, because the
adapter grants no client-side capability.

**A refusal carries its reason.** The JSON-RPC client keeps the error's
`data`, and the failure the panel shows says what is wrong and what to do
about it.

**A claim of demonstration carries the evidence it rests on.** A preset that
says it has been demonstrated names the runtime, the version, the day and what
was observed, and the schema refuses a claim with nothing behind it. The
panel shows that evidence under the template it belongs to.

**The fake ACP agent now behaves like a real one.** The fixture refuses a
`session/new` without `cwd` and `mcpServers`, and it can refuse a session the
way a runtime with no provider does — so the defect the real runtime exposed
is now a test.

## Scope and compatibility

**Owned paths** — the preset catalogue, the adapters package, the scripts, the
tests, and the contract.

**Compatibility.** The new preset is additive: `hermes-http` is still there
for a gateway deployment, and a connection created from it changes nothing.
The ACP adapter's session request now carries the two fields the protocol
requires, which is a fix and not a change of shape — an agent that ignored
them was accepting a request the protocol does not describe.

## Acceptance criteria

- [x] The catalogue carries a preset for the surface the installed Hermes
      publishes.
- [x] A runtime can be asked whether it answers, through the product's own
      adapter, and the answer is printed.
- [x] The handshake against the installed Hermes answered, and its
      capabilities were reported.
- [x] A turn completed against the installed Hermes, through the product's own
      adapter, with the runtime's own answer.
- [x] The two defects the real runtime exposed are fixed and tested.
- [x] The preset that was run carries the evidence the claim rests on, and a
      claim without evidence does not parse.

## Not in scope

- **The other four runtimes.** Codex, OpenCode, Pi and OpenClaw are not
  installed here, so nothing about them was observed, and their presets still
  carry `verified: false`.
- **The credential.** The turn needed a provider, and the owner’s MiniMax
  credential was written into Hermes’s own `.env` to supply one. Personal OS
  never held it, and it is not in this repository. **The credential is
  short-lived**, so the demonstration is dated rather than standing: what the
  template proves is the shape of the integration, and the owner’s provider is
  the owner’s business.
- **A permanent provider.** Nothing in Personal OS configures a runtime’s
  model, and nothing should: the runtime keeps its own credential, and the
  preset says so.
