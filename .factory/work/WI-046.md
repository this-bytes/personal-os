## Problem

**The published contract was one route behind the code, and the pipeline said
so.** The verification run on the tree carrying WI-031's implementation
(`414996c`, run `39522331290`) was red:

    FAIL  src/__tests__/published-shapes.test.ts > the two published shapes >
           publishes the counts of routes and audit entries the code has
    AssertionError: expected 35 to be 34

`CONTRACTS.md`, in `### The measures route`, published **34** mutating routes
and **20** that write an audit entry at the route level. The code registered
**35** and **21**. WI-031 added `POST /api/executions/:id/resolve` — a mutating
route that writes its audit entry in its own handler — so both counts went up
by one and the published numbers did not follow. **The contract went stale
quietly, and the only thing that noticed was a test reading the contract
against the code.**

**The correction is made** (`50b908d`, `CONTRACTS.md` only): 34 → 35,
20 → 21, and the prose "thirty-four" → "thirty-five". **The twelve stays
twelve**, and the table of routes that write no audit entry does not change —
the new route audits, so it is not in it.

**And one stale number is left, in Probe's own file.** The test's comment says
_"twelve of the thirty-four mutating routes write no audit entry at all"_. That
is a published number in a file the lead does not own, and it must not outlive
the correction it describes.
