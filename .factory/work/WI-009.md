# WI-009 — In coordinator mode, only the coordinator may hand the turn over

**Owner:** Cog
**Verifier:** Probe
**State:** triage
**Not scheduled until:** the owner answers the question below. If the answer
is "any participant may hand over", this item closes instead of being built —
the comment is wrong, not the code.

## Problem

`apps/server/src/modules/conversations/routing.ts:156-183` documents that
_"Only the coordinator may delegate, and delegation is explicit"_ — and the
code does not enforce it.

Verified in source, line by line:

- Line 157 finds the coordinator: `participants.find((p) => p.id ===
conversation.coordinatorId)`.
- Line 158 takes its connection id.
- Lines 160-170 are the agent-message branch. If the message mentions
  anyone, the routing decision is
  `{ targets: unique(mentioned), reason: 'Delegated by the coordinator.' }`
  — **and the sender is never compared to the coordinator.** The `coordinator`
  and `coordinatorConnection` variables are read only in the human-message
  branch, at line 172.

So in coordinator mode **any** agent's message that mentions another
participant routes to that participant. Every participant can dispatch. The
mode promises a single dispatcher and delivers a free-for-all, while
reporting — in the reason string the owner would see — that the coordinator
delegated.

## Why now

Coordinator mode is the mode the owner would pick for "one agent dispatches
the others". Today it does not hold that promise, and the failure mode — a
ping-pong between two agents — is stopped by a counter rather than by
evidence: the loop-breaker is a set of limits (depth 5, turn count, duration,
spend — `routing.ts:69-108`), not a rule about progress.

It is also the smallest item in this batch, and it is a defect against a
promise the code already makes in a comment — which is the cheapest kind of
defect to fix and the easiest to get wrong by accident later.

## The question that decides this item

**Was coordinator mode ever meant to let any participant hand the turn over?**

- If **no** — the comment is right and the code is wrong. This item is
  implemented as written below.
- If **yes** — the comment is wrong, and this item closes rather than being
  built. The comment is corrected instead, and the reason is recorded here so
  the question is not asked again.

This is a question about the product's intent, not about the code, and only
the owner can answer it. Chief asked it on 2026-10-20.

## Acceptance criteria

- [ ] In coordinator mode, a message from a participant that is **not** the
      coordinator does not route to another participant, and the routing
      decision says why.
- [ ] In coordinator mode, a message from the coordinator routes to mentioned
      participants, as today.
- [ ] `mentions` and `autonomous` modes are unchanged.
- [ ] A routing test covers the coordinator-only rule, and it **fails against
      the current implementation**.
- [ ] The routing decision's reason string tells the owner what happened, and
      it does not claim the coordinator delegated when the coordinator did not.
- [ ] `npm run typecheck` and `npm run test` pass.

## Not in scope

- The progress-based pause. The plugin pairs the handoff rule with
  _"Repeated handoffs without new tool progress detected. Discussion paused;
  add instructions to continue. Independent tasks keep running."_ That is a
  different guarantee and a different item (C-12).
- Routing modes `mentions` and `autonomous`.
- The delegation depth, turn, duration and spend limits.
- Any change to the persona layer, the approval resume, or the `unknown`
  state.
