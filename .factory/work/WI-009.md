# WI-009 — In coordinator mode, only the coordinator may hand the turn over

**Owner:** Cog
**Verifier:** Probe
**State:** verify — the second implementation landed in `3872dbc`; Probe's
verification of it is owed
**Implemented:** 2026-10-21, commit `6e7d347`. The tree was clear of the items
already in flight. This one crosses no published boundary — it enforces a safeguard that
`CONTRACTS.md` already publishes — so it needs no contract approval and no
owner answer. See "The question that decides this item" below.
**Re-implemented:** 2026-10-21, commit `3872dbc` ("Keep the coordinator rule on
the path that names a target"). Probe's review of `6e7d347` found the fix was
incomplete: the explicit-target path was still applied **before** the routing
mode was consulted, so a participant that named its target instead of
mentioning it was never asked whether it was the coordinator. `3872dbc` moves
the named-target handling inside each routing mode.

## Problem

`apps/server/src/modules/conversations/routing.ts:156-183` documents that
_"Only the coordinator may delegate, and delegation is explicit"_ — and the
code does not enforce it.

Verified in source, line by line:

- Line 157 finds the coordinator: `participants.find((p) => p.id ===
conversation.coordinatorId)`.
- Line 158 takes its connection id.
- Lines 160-170 are the agent-message branch. If the message mentions
  anyone, the routing decision is
  `{ targets: unique(mentioned), reason: 'Delegated by the coordinator.' }`
  — **and the sender is never compared to the coordinator.** The `coordinator`
  and `coordinatorConnection` variables are read only in the human-message
  branch, at line 172.

So in coordinator mode **any** agent's message that mentions another
participant routes to that participant. Every participant can dispatch. The
mode promises a single dispatcher and delivers a free-for-all, while
reporting — in the reason string the owner would see — that the coordinator
delegated.

## Why now

Coordinator mode is the mode the owner would pick for "one agent dispatches
the others". Today it does not hold that promise, and the failure mode — a
ping-pong between two agents — is stopped by a counter rather than by
evidence: the loop-breaker is a set of limits (depth 5, turn count, duration,
spend — `routing.ts:69-108`), not a rule about progress.

It is also the smallest item in this batch, and it is a defect against a
promise the code already makes in a comment — which is the cheapest kind of
defect to fix and the easiest to get wrong by accident later.

## The question that decides this item — answered from the published contract

**Was coordinator mode ever meant to let any participant hand the turn over?**

Chief asked the owner on 2026-10-20, and then found the answer in the
published contract, which is the better place to look:

- `CONTRACTS.md:91-92` — _"**Coordinator mode.** A designated agent receives
  the request and may delegate to other participants according to its
  capabilities and authorisation."_
- `CONTRACTS.md:99-107` — **Mandatory routing safeguards**, and the fifth
  bullet is: _"Only one owner is responsible for coordinating a particular
  delegation."_

A mandatory safeguard is not a style note. In coordinator mode, if any
participant may hand the turn over, then several owners can each be
responsible for a delegation in the same conversation, and the safeguard is
broken. The contract therefore already says: **the coordinator, and only the
coordinator, delegates.** The code comment at `routing.ts:161` says the same
thing. The brief says the same thing.

**So this is not a contract change, and it is not gated on the owner.** It is
a defect against a published mandatory safeguard, and it is ready to build.
The only thing this item changes is the code and the routing reason string
agreeing with the contract that is already published.

If the owner says the intent was ever different, the item closes and the
contract changes instead — but that would be a change to a published
mandatory safeguard, and it would need the migration plan and the owner's nod
that a contract change always needs. Chief's reading is that the contract is
right, the code is wrong, and the code should be fixed.

## Chief's ruling — the owner path in coordinator mode, 2026-10-21

`3872dbc` moved the explicit-target handling inside each routing mode. That
fixed the defect Probe found, and it changed one behaviour that no test
pins, which the commit message says out loud:

> The one behaviour no test pins: in coordinator mode the owner's own message
> now reaches the coordinator even when it names a participant, which is what
> the mode has always done with a mention.

**The ruling: the new behaviour is correct, and it must be pinned.**

Before `3872dbc`, an owner message that named a participant was handled by the
explicit-target branch, which sat above the routing mode, so the named agent
was woken directly and the coordinator never saw the request. After
`3872dbc`, in coordinator mode the owner's own message reaches the coordinator
even when it names a participant — the same thing that already happened when
the owner _mentioned_ someone.

Two things make this the right reading, not a regression:

1. **The mode has one promise.** `CONTRACTS.md:141-142` — _"A designated agent
   receives the request and may delegate to other participants."_ The owner
   addressing one agent is still a request; the coordinator is the one who
   decides who acts. A mention and a named target are two spellings of the
   same request, and the mode must not change its answer because the owner
   spelled it differently. The rule is about who delegates, not about how the
   delegate is spelled.
2. **The alternative is a hole.** If the owner could reach an agent directly by
   naming it, then the safeguard _"Only one owner is responsible for
   coordinating a particular delegation"_ (`CONTRACTS.md:155`) would hold for
   one spelling of a request and not the other — and a participant that named
   its target would get a free-for-all the mention path does not offer.

The reason string carries the change honestly: _"In coordinator mode the
coordinator hands the turn over, so the named participants were not woken
directly."_ The owner is told what happened, which is the same standard the
rest of this item is held to.

**What is owed:** a test that pins this behaviour, so it cannot change
silently. Probe owns every test file, so that test is Probe's.
