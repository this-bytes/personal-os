## The problem

**`CONTRACTS.md` publishes `ResolveExecutionInput.note` with no bound, and the
code caps it.** Measured on `main` on 2026-10-21:

| Where                                            | What it says                                                                          |
| ------------------------------------------------ | ------------------------------------------------------------------------------------- |
| `CONTRACTS.md:163-166` — the block               | `note?: string;` — **no bound**                                                       |
| `CONTRACTS.md:172` — the prose under it          | _"`note` is optional, and it is the owner's own words."_ — **nothing about a length** |
| `apps/server/src/api/executions.ts:9` — the code | `note: z.string().max(2_000).optional()` — **the cap is 2,000 characters**            |

**A client written against the published shape may send a note longer than the
cap and be refused.** The route parses the body with the code's own schema
(`parseBody(resolveSchema, request.body)`), so a 2,001-character note fails
validation — and the contract never said that there was a cap.

**And the contract already knows how to publish one.** Two other fields publish
their bounds in the house way — as a trailing comment on the field's own line:

- `CONTRACTS.md:376` — `role?: string; // 1–200 characters, one line, shown to the owner`
- `CONTRACTS.md:377` — `instructions?: string; // up to 8,000 characters, shown to the agent`

**So this is a gap in a shape the contract publishes correctly elsewhere**, and
not a new kind of promise. The fix is the house form, not a new section.

**Why it is the last thing standing between WI-031 and its acceptance.** WI-031's
own seventh criterion is _"the published shape matches the code exactly, member
for member, checked against the implementation, not against the proposal above."_
A shape published wider than the code allows does not match the code, member for
member. WI-031's implementation is landed, its verification is done, and its own
status paragraph is waiting — **and a status paragraph that says _"the shape is
