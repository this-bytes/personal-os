## The problem

**An owner who set a mode changed nothing, and the panel said otherwise.**

A workspace carries its mode twice. The column `autonomy_mode` is what the
panel shows and what `GET /api/workspaces/:id` returns. The policy
`autonomy_policy.mode` is what the resolver reads and what
`GET /api/autonomy-policy` reports. `PATCH /api/workspaces/:id` accepted
`autonomyMode` and wrote **the column only** — the route's body schema names
`name`, `description` and `autonomyMode` and nothing else, and the service
wrote the two fields independently.

So the owner set `autonomous`, the panel showed `autonomous`, and the policy in
force stayed `manual`. The setting was a lie in the only sense that matters:
it told the owner something false about what the agent was permitted to do.

**This is not a new defect.** WI-085's attack test has carried a case for it
since 2026-10-21 — _"the panel shows `workspace.autonomyMode` and
`PATCH /api/workspaces/:id` is the only way an owner can set a mode, but the
policy in force is resolved from `autonomyPolicy.mode`"_ — and it has been red
ever since, **by design**, because the attack test was written to leave the
owner's decision open.

## What this item does, and what it does not

**It makes the two surfaces agree, and it does not decide the question.**

The fix is in the service layer, which is the single choke point every write
goes through: a patch that names the mode writes **both** the column and the
policy's mode, and a patch that names a policy carries the policy's mode into
the column. Whichever way round the change arrives, the panel and the policy
in force hold the same mode.

**That is about the setting being honest, not about the mode being in force.**
The mode is still enforced nowhere. `CONTRACTS.md` still says so, and this
item adds a sentence saying that the mode the owner sets is the mode that is
in force **and** that the mode is still enforced nowhere and what it is to
mean is still the owner's decision.

**Which field is authoritative is still the owner's call, and this item does
not make it.** It removes the possibility of the two disagreeing through the
owner's own path, and it leaves the field that a future write path would read
as the open question.

## The acceptance criteria

- [x] **A patch that names the mode writes both.** `PATCH /api/workspaces/:id`
      with `autonomyMode: 'autonomous'` leaves the panel and the policy in force
      both saying `autonomous`.
- [x] **A patch that names a policy moves the panel.** The service is the
      choke point, so the two are written together whichever way round the change
      arrives.
- [x] **A patch that names neither leaves the mode alone.** A rename does not
      touch the policy.
- [x] **The contract says so.** The mode section says the mode the owner sets
      is the mode that is in force, and says in the same breath that the mode is
      still enforced nowhere and what it is to mean is still the owner's decision.
- [x] **The published contract is not otherwise changed.** The route's table
      entry still reads "Read and update a workspace" — the body shape is not
      published, so this is not a shape change and needs no migration.

## The proof

Four cases in `apps/server/src/__tests__/autonomy-policy-surface.test.ts`,
in the file that already holds the two published surfaces of the policy.

**Two mutation proofs, each red and each restored:**

1. **The policy no longer follows the column.** Removing the line that copies
   the mode into the policy turned **three** of the four red, with the
   message the owner would see:

   > the panel shows "autonomous" and the policy in force says "manual": the
   > mode the owner can see and set has to be the mode that is in force

2. **The column no longer follows the policy.** Removing the line that copies
   the policy's mode into the column turned the case that moves the panel red.

Both were restored and the file is green: **18 passed**.

## What is still the owner's decision

**Whether `manual` means the agent may not begin work on its own initiative.**
That is WI-085's other red case, and it is red by design: the effective mode
is resolved, published and consulted by nobody, so a delegation still begins
work under `manual`. **This item does not touch that**, because the contract
says the meaning of the modes is the owner's decision and it is not settled.
