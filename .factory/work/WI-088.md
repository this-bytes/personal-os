# WI-088 — The ledger split into what it is and what it was

**Owner:** a worker, under Chief
**Verifier:** Chief
**State:** implement — dispatched 2026-10-21 as part of the factory-mechanics phase.
**Numbered:** 2026-10-21 by the session that owns the number space for this push.

## The problem

`.factory/INTAKE.md` is **9,900 lines**. The doctrine says what that file is:

> `FACTORY.md:257` — "It lands in [`.factory/INTAKE.md`](../.factory/INTAKE.md),
> which is the queue of wants that have not yet become work items. That file
> also holds the standing questions Chief asks when a want is under-specified."

That is lines 1–1033. The queue, the stated scope, the strategy decisions, the
owner's decisions, the candidates, the order, the borrowing rule, how a want
becomes a work item, the standing questions, the rules that apply to every
want, and the tiebreak.

**Lines 1034–9,999 are something else.** They are timestamped process
narrative — the factory writing about itself:

> `## The push — 2026-10-21 11:30`
> `## The watchdog run at 19:02 — the last three checks did not complete`
> `## The floor at 20:45 — two merges, one near-miss, and a runtime that stopped`
> `## Correction — 2026-10-21 19:58: a timestamp of mine was wrong`
> `## Two corrections to this session's own account — 2026-10-21 19:57`

Every one of those is a careful, true observation. **None of them is state.**
The history of the factory is the git history; writing it a second time into
the file that _is_ the state duplicates it in the one place every agent has to
read.

The cost is measurable. Every factory cycle starts by reading this file. At
10,000 lines it is the single largest thing in an agent's context, and 8,800 of
those lines say nothing an agent needs to act.

## What this item does

Split the file in two, at the boundary that already exists.

- **`.factory/INTAKE.md`** keeps lines 1–1033 — the state. A short pointer at
  the top says where the history went and why.
- **`.factory/history.md`** receives lines 1034 to the end, **verbatim**, under
  a header that says what it is: the factory's process record, kept for the
  record, and not part of the state.

**Nothing is deleted.** This is a move, not a trim.

## The rules

1. **The moved text is byte-identical.** The two files, concatenated, must
   reproduce the original exactly. Prove it in the report — do not assert it.
2. **The state half is not edited beyond the pointer.** Do not reword a
   decision, do not tidy a table, do not fix a typo in a decision the owner
   made. This item moves text; it does not edit it.
3. **No content is lost.** A section that is not obviously narrative stays in
   the state half. If you are unsure whether a section is state, it stays.
4. **The pointer is short.** Three or four lines, and a link. It is not a
   summary of the history and it is not a new diary entry.
5. Do not touch any other file. `FACTORY.md` needs no change: every reference
   it makes to `INTAKE.md` is a reference to the state, and the state stays
   where it is.

## Why this is a factory-mechanics fix and not a policy change

The rule was never "write a diary". `FACTORY.md` says the repository is the
state, and a process narrative is not state — it is a log of a log. On
2026-10-21, 230 of the repository's 437 commits touched nothing but
`.factory/`, and this file was revised 180 times. The two schedules that
produced most of that have already been rewritten to stop writing here.

This item makes the file match the doctrine that was always there.
