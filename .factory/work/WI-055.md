## Acceptance criteria

- [ ] **The turn** — an execution with a `conversationId` and no `taskId` — is
      first-class, and `executionStatusSchema` grows by `committed` and `lost`.
      Nothing is reclassified.
- [ ] **The capability view is pinned at admission**, and a capability or
      grant change takes effect on the next turn. A turn recorded before the
      change has no view, and the API reports it as absent.
- [ ] **The five-step canonical history commit is implemented**, in the
      published order, and the reply message's status moves from `streaming` to
      `complete` only when the commit is acknowledged. A crash between the write
      and the commit leaves the message `unknown`.
- [ ] **Steer and queue work end to end.** A message carries
      `delivery: 'steer' | 'queue'`, default `queue`. A steer is delivered into
      the running turn, and a connection whose adapter cannot take input
      mid-turn has its steer degraded to a queued message **and says so**. A
      steer that the turn never consumed is delivered to the next turn.
- [ ] **The routing change has a test in `routing.test.ts`** — a steer targets
      only the running turn's agent, wakes no other participant, and does not
      count as a new turn for the duplicate check. AGENTS.md requires it.
- [ ] **Fork and rewind work**, are audited, and produce a conversation and a
      turn that match the published contract.
- [ ] **The delegation tree is a tree**: a parent reference beside
      `origin.depth`, the seven published statuses, delivery recorded
      separately from consumption, a consumption candidate confirmed only when
      the parent turn's terminal state is committed, and `lost` settled after a
      restart and never re-run.
- [ ] **The existing `unknown` behaviour is unchanged** — a test that exists
      today still passes untouched.
- [ ] `npm run typecheck`, `npm run test`, `npm run format:check`,
      `npm run build` and `npx tsx scripts/smoke.ts` pass.
