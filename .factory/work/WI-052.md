**Numbered:** 2026-10-21 — WI-046 through WI-061, taken by the session that owns

## The owner's answer, and the gap it names

**The owner's answer, 2026-10-21: publish the interaction model as one contract
revision now; land the code as one work item after the in-flight interaction
items.**

The gap: Personal OS has no per-turn capability pinning, no canonical-history
commit, no mid-turn steering, no session fork or rewind, no parent-child work
tree, and no `lost` for delegated work whose executor has gone. The harness has
all six, and the licence permits reading it.

## Acceptance criteria

- [ ] **`CONTRACTS.md` carries the model in full**: the turn, the capability
      view, the five-step canonical history commit, steer and queue with the
      capability gate and the degradation rule, fork and rewind, the delegation
      tree with delivery versus consumption and `lost`, the routes, the events,
      and the migration note.
- [ ] **The migration note says what a client written before the change does**,
      and that no record is rewritten.
- [ ] **The entry says plainly that the code does not implement it yet**, and
      names the work item that carries it. A contract that describes a future
      is a contract, and it must say which future.
- [ ] **The routing change is published with its guard**: a steer targets only
      the running turn's agent, does not wake other participants, and does not
      count as a new turn for the duplicate check — and it weakens none of the
      mandatory routing safeguards.
- [ ] **What the model does not change is stated**: the factory ledger, the
      resource contract, and the acceptance rule.
- [ ] **The contract is one revision, not five.** The owner chose the whole
      model at once, and the cost of that is the size of this entry.

## Not in scope

- **The implementation.** WI-055.
- **The worker-internal patterns** — the context budget, the result archiver,
  the tool eligibility chain. They are WI-056, and they are not client
  visible, so they are not in the contract.
- **The `acceptsSteering` capability.** It is in the contract here and in the
  schema as of WI-053, because the MCP adapter reports it and the
  degradation rule needs it.

## Notes

**The contract was published before the code on purpose.** A model this large is
easier to get right whole than in halves, and prose is cheap to change while it
is still prose. The implementation is one work item for the same reason: a
coherent interaction model is easier to land whole than in five pieces that
each break the ones before them.
