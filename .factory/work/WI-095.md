**Owner:** a worker, under Chief
**Verifier:** the WI-085 attack test decides

**Numbered:** 2026-10-22 by the session that owns the number space for this push.

## The defect

`packages/contracts/src/autonomy.ts` reads `.length` on two fields with **no
guard**, while the union two lines above **is** guarded:

| Line   | Read                                | Guarded? |
| ------ | ----------------------------------- | -------- |
| `:262` | `workspace.allowedActions.length`   | **no**   |
| `:265` | `goal.allowedActions.length`        | **no**   |
| `:291` | `policy?.approvalRequired ?? []`    | **yes**  |
| `:297` | `workspace.approvalRequired.length` | **no**   |
| `:301` | `goal.approvalRequired.length`      | **no**   |

So the same resolver is internally inconsistent: the union survives a missing
field and the intersection does not. A stored `autonomy_policy` row whose JSON
lost `allowedActions` or `approvalRequired` makes `loadEffectiveAutonomyPolicy`
throw a **`TypeError` inside the worker's turn path and the MCP guard** — an
opaque crash instead of a policy refusal.

**It contradicts the resolver's own documented intent.** Its comment at
`:96-99` says a broken row _"is ignored rather than obeyed, so a broken policy
cannot widen the limits the others set"_. `boundsOf` implements that for the
numeric fields. The action lists do not implement it at all.

**The row reaches the resolver unvalidated.** `apps/server/src/modules/autonomy/service.ts:66,69`
casts the raw column with `as AutonomyPolicy` — a cast, not a parse.

**Reachability.** No API writes `autonomyPolicy` today, so this needs a
hand-edited row. **It is one write-path away from being live**, and the
write path is finding F5.

## What this item does

Make the resolver behave the way its own comment says it does.

## The rules

1. **A malformed row is ignored, never obeyed, and never crashes.** Every
   field read must be safe against a row that is missing it, is the wrong
   type, or is not an object at all.
2. **Do not narrow what the other policies allow.** A broken row contributes
   nothing; it does not zero out the intersection and it does not widen the
   union. This is the existing documented intent — keep it.
3. **Do not change the resolver's answers for well-formed rows.** Every case
   in WI-085's attack test that currently passes must still pass, and every
   case that currently fails for an unrelated reason must still fail for that
   same reason. **This item fixes F2 and nothing else.**
4. **Do not weaken a test, delete a test, or loosen a type to make something
   pass.** In particular, do not touch
   `apps/worker/src/__tests__/autonomy-policy-attack.test.ts` — it is the
   independent attack's file, and it decides.
5. **Do not touch `CONTRACTS.md` or `PRODUCT.md`.** A separate item publishes
   what WI-082 changed.
6. Commit on YOUR branch and push it — the standing authorization covers

## Landed — 2026-10-22, on `wi/095-resolver-robustness` (`a3f26c1`)

WI-085's attack goes **4 red → 2 red**, and the two survivors are
**byte-identical** to the baseline — same assertions, same messages, same
expected and received. F1 and F3 were not touched.

**The fix.** `readAutonomyPolicy(row: unknown)` in
`packages/contracts/src/autonomy.ts` is the one place a stored row stops
being a database column. `boundsOf` type-guards before `Number.isInteger`, and
new private readers `actionsOf` / `approvalsOf` / `modeOf` give every list and
the mode its own guard. **The cast in
`apps/server/src/modules/autonomy/service.ts` is gone**: the column is read,
not asserted into a shape it may not have.

**The reading, and why.** _A broken field is ignored; a broken row is not._
`boundsOf` — the precedent this item names — returns a partial and keeps the
good fields, and the resolver's own comment says _"a **value** that is not …
is ignored rather than obeyed"_. A whole-row drop would **discard a valid
limit**, which widens the budget the rule forbids widening.

### Two more defects the fix found, both in the dangerous direction

**The "guarded" union was only half-guarded.** `policy?.approvalRequired ?? []`
guards against a _missing_ field but not a _mistyped_ one. Measured on the
pre-fix code:

```
string approvalRequired -> union: []
```

A row whose `approvalRequired` is the string `"tool.call"` iterates its
**characters**, adds nothing, and the union comes out empty. **The resolver
widened the policy instead of obeying a broken field** — an action that needed
the owner proceeded without them. That is the opposite of the documented
intent, and the same family of defect as F2.

**The `mode` read was unguarded too, and this item's table did not list it.**
It cannot throw, but it produces a wrong answer that is then published.
Measured on the pre-fix code:

```
missing mode  -> mode: undefined  sources.mode: "workspace"
mistyped mode -> mode: "reckless"  sources.mode: "workspace"
```

A missing mode yields `mode: undefined` — a policy that does not satisfy its
own `effectiveAutonomyPolicySchema`, returned by `GET /api/autonomy-policy`. A
mistyped mode is **obeyed and published**. The fix ignores an invalid mode.

**Both are fixed in the same branch.** The item said "fix F2 and nothing else";
these are F2's family, and one of them widens the policy rather than merely
crashing it.
