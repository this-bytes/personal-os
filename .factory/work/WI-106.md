### 4. `data` and `template` merge — the behavioural break

**Before** — `24480b7:CONTRACTS.md:630-633`:

> `template` names the template to start from: its `spec` is the resource's
> `data`, and its `type` must equal the `type` the call asks for. `data` and
> `template` are **mutually exclusive** — a call that supplies both is refused,
> because there is no published answer to which of the two wins.

**After** — `CONTRACTS.md:685-693`:

> **`data` and `template` are not mutually exclusive — they merge.** `template`
> names the template to start from, and its `type` must equal the `type` the
> call asks for. `data` is the caller's own values, and the resource's `data` is
> the template's `spec` with those values merged into it. **A call that carries
> both is no longer refused — it is answered**, and the values the call did not
> name are the template's.

The merge rules were **published as the implementation has them**
(`CONTRACTS.md:699-721`), and they are the rules `mergeTemplateSpec` implements
(`apps/server/src/modules/resources/templates.ts:496-543`):

- objects merge key by key, recursively;
- an array is replaced whole;
- a change of the shape key (`kind` for a data source, `scope` for a memory)
  replaces the whole spec;
- `automation.trigger`, `automation.action` and `memory.value` are replaced
  whole whatever they are;
- a dashboard's widgets merge by the widget's own `id` — named by the same id is
  updated field by field, unnamed survives, added is appended after the
  template's, and a widget whose `type` changes is the caller's whole;
- the merge never refuses; the owning provider judges the merged spec.

**Evidence — the merge was run, not inferred.**

- `resource.create` with `template: { id: "dashboard.metrics" }` and
  `data: { refreshSeconds: 30, widgets: [{ id: "summary", title: "Records
(mine)" }] }` answered with the widget `summary` carrying the caller's title
  and the template's `type` and `binding`, the widget `recent` untouched,
  `refreshSeconds: 30` and `published: false`.
- A document from `document.brief` with `data: { tags: ["mine"] }` answered with
  `tags: ["mine"]` — the array replaced whole — and the template's `format` and
  `content` intact.
- A data source from `data-source.json` with `data: { kind: "http", url: … }`
  answered with **no `payload`** — the shape key changed, so the whole spec was
  replaced.

**The test that pinned the old rule changed with it.** The test named _"refuses a
call that carries both a spec and a template"_ is now _"merges the values it is
given into the template's spec"_
(`apps/server/src/__tests__/resource-templates.test.ts:537`). The contract and
the test now agree.

### 13. The refusal message wording (Chief's addition)

**Decision: the wording is published as _not fixed_, not verbatim.**

**Added** — `CONTRACTS.md:923-931`:

> **The refusal names the action; the rest of its wording is not fixed.** A
> refusal the autonomy policy makes says which action was refused, in a sentence
> the owner can act on, and it carries the action and the allowed actions in
> `details` … **The wording itself is not part of the contract**: the sentence is
> composed from the policy in force, so it changes when the policy changes, and a
> client must not match on it. A client matches on the `code` — a refused action
> is `forbidden` — and on the `action` in `details`. The one exception is a
> refusal whose message is fixed in the code and published in this section, such
> as "An agent may only reach its own memory."

**Why.** `autonomyActionRefusal` (`packages/contracts/src/autonomy.ts:374-381`)
composes its sentence from the policy in force — the allowed actions and the
level that set them — so the string changes whenever the policy changes. A
client would have to match on the `code` and on `details.action`, not on the
prose. Publishing the prose verbatim would publish a sentence with a variable
middle and would make it look fixed when it is not. **The house's preference —
"publish what a client would have to match, and say plainly when a string is not
fixed" — points this way.** The one message the house does publish verbatim is
the fixed one, "An agent may only reach its own memory.", and this entry says so.
