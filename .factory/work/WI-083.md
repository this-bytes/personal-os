# WI-083 — The documented gaps that the code has already closed

**Owner:** Wren
**Verifier:** Probe
**State:** verify — **the sweep is done: five documents corrected, ten claims
confirmed still true, and two stale contract entries reported** (`5aa9d81`,
`8549f92`, `4b4cf95`, `b7544c5`, `dfdc7eb`) … Probe verifies it.
**Numbered:** 2026-10-21 by the session that owns the number space for this push.

## The problem

The documentation is **ahead of the code in some places and behind it in
others**, and the factory has been paying for both.

The clearest instance of "behind": `ARCHITECTURE.md` §9 still says

> **ACP sessions are not resumed.** … The published contract has already moved:
> `CONTRACTS.md` says a turn re-enters the same session when the adapter reports
> `persistentSessions` (WI-007). **The code has not caught up.**

It has caught up. `packages/agent-adapters/src/acp.ts:213` implements
`resumeSession`, `apps/worker/src/executor.ts:375` calls it, and both
`apps/server/src/__tests__/approval-resume.test.ts` and
`apps/worker/src/__tests__/approval-resume.test.ts` cover it. `SECURITY.md:55`
carries the same stale claim.

**A stale "gap" in the docs is an invitation to rebuild something that
already exists.** That is how a factory spends a day of model budget and
produces a commit that changes nothing — which is exactly what 380 of the
437 commits in this repository did.

## What this item does

Sweep every published document for a claim that the code has already closed,
and correct the claim.

The documents in scope: `ARCHITECTURE.md`, `PRODUCT.md`, `CONTRACTS.md`,
`SECURITY.md`, `README.md`, `docs/strategy.md`, `docs/decisions/**`.

## Acceptance criteria

- [ ] Every "not implemented yet", "the code has not caught up", "not yet
      enforced" or equivalent claim in the documents above is checked against
      the code, and each one is either corrected or confirmed still true.
- [ ] A claim is only corrected when the code **and a test** support the
      correction. A claim corrected on the strength of a reading is worse than
      the stale claim.
- [ ] Where a claim is confirmed still true, the item says so explicitly — a
      gap that is real stays a gap, and this item must not quietly delete one.
- [ ] `CONTRACTS.md` is not touched. It is a published contract; a change to
      it needs a migration plan and the owner's nod. If a contract entry is
      stale, report it instead of editing it.
- [ ] `npm run format:check` passes.

## Gate

`npm run format:check` · `npm run test`

## Deliverable

The report lists each claim, what the code says about it, and what was
changed — with the file and line for both. A claim nobody checked is not
listed as checked.

## Confirmed still true — a real gap stays a gap

1. **`PRODUCT.md:152` — "The policy is stored; it is not yet enforced."** The
   policy is written and read back (`apps/server/src/db/schema.ts:52-53`,
   `:300`; `packages/contracts/src/common.ts:39-55`) and nothing reads it to
   make a decision. WI-082 is implementing it and has not landed.
2. **`PRODUCT.md:188` — "The first measure has its data for four of the six
   kinds… an automation and a task record their author as `system`."**
   `apps/server/src/modules/resources/service.ts:203`, `:293` and `:448` still
   write `createdBy: 'system'`. WI-033 has not landed.
3. **`PRODUCT.md:197` — "every entry written today records a success whether
   the action succeeded or not."** The route helper writes `result: 'success'`
   (`apps/server/src/api/helpers.ts:62`), the audit service defaults to it
   (`apps/server/src/modules/audit/service.ts:79`, `:92`) and carries
   `'success' | 'failure' | 'unknown'` (`:19`), and **no writer anywhere
   produces `queued`, `failed` or `succeeded`**.
4. **`PRODUCT.md:287` — "The panel does not do this yet."** (one accent with
   one meaning) The accent is indigo (`apps/web/src/index.css:25-32`) and marks
   structure — the active nav item (`apps/web/src/components/AppShell.tsx:120`),
   an agent's messages (`apps/web/src/components/ChatMessageList.tsx:97`,
   `:102`) and the app's badge (`AppShell.tsx:92`); the event stream is a
   four-colour traffic light — emerald, amber, red, slate-600
   (`AppShell.tsx:33-48`). WI-071 is not merged.
5. **`PRODUCT.md:49` — "no adapter implements it. No external status is
   retained, no execution is ever marked as externally owned, and the panel
   shows neither."** The worker asks for an external task id
   (`apps/worker/src/executor.ts:420`) but **no adapter has `externalTaskId`**;
   no route accepts `executionOwner`; and `externalRef` and `executionOwner`
   appear nowhere in `apps/web`.
6. **`docs/strategy.md:65` — "the skill layer, not built."** No file in the
   tree carries "skill" in its name.
7. **`docs/strategy.md:320` — W7's gate script "is not written."**
   `scripts/verify-licences.ts` is absent from the tree, the root manifest has
   no `verify:licences` entry, and the workflow has no licence step.
8. **`docs/strategy.md:634` — W9 "is not numbered, and it is not dispatched."**
   It has neither.
9. **`docs/strategy.md:195` — W3's gap (history and take-back) "is still
   open."** There is **no undo, revert or rollback anywhere** in
   `apps/server/src`, `apps/web/src` or `packages/contracts/src`. ADR 7 says
   the same at `:114`, and it is true.
10. **`README.md` — no stale gap claims.** The one checkable claim holds: "the
    setup screen only runs once, and no route changes it afterwards" — auth's
    routes are status, setup, login, logout, me and owner-token
    (`apps/server/src/api/auth.ts:25`, `:29`, `:52`, `:72`, `:79`, `:83`), and
    none changes a password.
11. **`docs/strategy.md:638-680` — the licence census is exact.** 375 entries
    read in place, 16 read from the package's own `license` field, 97 read
    from a published identifier, and all eleven licence counts in the table
    match `docs/dependency-licences.json` — which covers all 488 third-party
    lockfile paths plus the six workspaces, with none missing.
