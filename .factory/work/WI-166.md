# WI-166 — After a restart, surviving runs are reconnected and the rest are named uncertain

**Owner:** the implementing agent for the slice (Cog — the implementation
engineer for the server, the worker and the contracts).
**Verifier:** Probe, the verification engineer, independently.
**State:** implement
**Branch:** wi/166-restart-reconciliation
**Base:** main at intake (68bbd79); cut the branch from the current
`origin/main`.

## Problem

`docs/roadmap.md` (R0, "Next bounded slices", 4) and the owner's directive
(`.factory/DIRECTIVE.md` §6.4) name the same slice:

> Test restart/reconciliation and unknown outcomes with side effects. Keep the
> current no-blind-replay guard; do not wait for a lease to expire and assume
> the previous executor stopped.

After a restart the product cannot say what happened to a run that was in
flight. The two available answers are both wrong: **replay** it (a duplicate
side effect the owner never asked for) or **assume it stopped** (a lease
expiry is not evidence that the executor stopped). The honest third answer —
_the outcome is uncertain_ — is not available.

**Outcome:** after a restart, a surviving run is reconnected and its state is
reported as observed; a run whose outcome cannot be known is reported as
uncertain, with the evidence for the uncertainty.

## Scope and compatibility

- **Owned paths:** the restart path's reconciliation of running executions, the
  outcome-unknown state, and the terminal-event rules that depend on it — in
  `apps/server` and the worker.
- **Boundaries:** the existing no-blind-replay guard is **kept**, not replaced;
  the work is to make the uncertain case nameable.
- **Compatibility:** a restart never re-executes a run with possible side
  effects on the owner's behalf; the states the UI shows for a recovered run
  are the states it shows today plus `uncertain`.
- **Data migration:** none in this slice. Where an execution's shape changes,
  it is converted at the boundary.

## Acceptance criteria

- [ ] After a restart, a run that survived is reconnected and its state is
      reported as **observed**.
- [ ] A run whose outcome cannot be known is reported as **uncertain**, with
      the evidence that makes it uncertain.
- [ ] No blind replay: a run with possible side effects is never re-executed
      on the owner's behalf without the owner's turn.
- [ ] The existing no-blind-replay guard is kept, and a lease expiry is never
      taken as proof that the previous executor stopped.
- [ ] The restart case is covered by a check that runs the **real** path — a
      restart, not a simulated one.
- [ ] Applicable gates pass on the delivered revision.
- [ ] Independent review findings are resolved.

## Not in scope

- The R1 demonstrations — each is its own item.
- Blind replay as a recovery strategy, and any new lease semantics.
- New UI surfaces beyond what the `uncertain` state needs.

## Evidence

- Revision, the commands actually run and their results, runtime versions,
  inspectable output, limitations and the independent reviewer's verdict.
  A state label is a report, not proof.
