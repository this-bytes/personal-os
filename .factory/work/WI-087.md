## What this item does

Triage every stranded branch, and salvage what is worth keeping onto fresh
branches based on current `main`.

## The rules

1. **Never merge a stale branch into `main` as-is.** The deletion figures above
   are why. Merge or rebase onto current `main` first, then take the content.
2. **Never force-push, and never delete a branch.** Branches are closed by
   marking them superseded in their own item file, not by deleting them.
3. **One salvage at a time**, each on its own fresh branch off current `main`,
   each verified with the gates that apply to it.
4. **A branch whose content is already on `main` is superseded.** Record that
   and move on. Do not spend a cycle proving it twice.

## Priority order

1. **`wi/071-accent-one-meaning`** — twelve substantive commits of the Forge
   accent direction, stranded. This is Phase 4 of the 48-hour build and the
   largest block of real product work in the stranded set.
2. **`wi/044-vendored-sources`** — the owner's own borrow rule, half-landed.
   The inventory is done; the gate that proves it can fail is Probe's half and
   is not written.
3. **`wi/038-borrow-rule-gate`** — the gate wiring that goes with it.
4. Everything else — triage only. Most of it is superseded.

## The one gate that is red, and whose it is

`npm run test` fails on **one** assertion, and it is not the accent work's:

```
FAIL  src/__tests__/forge-briefs.test.ts > the amber collision >
      names ten usages across six files, and every one of them still holds amber
AssertionError: AppShell.tsx:37 no longer holds amber: expected
' * hollow ring read the same in a scr…' to contain 'amber-'
```

The cause is a cross-item collision, and it is worth stating precisely:

- WI-024's brief (`prototypes/briefs/02-material.md`) publishes the amber
  collision — ten lines across six files — and says **"Measured at
  `d343300`"**. That is a historical record, and it is accurate: at `d343300`
  the tree holds amber on exactly ten lines in exactly those six files.
- WI-024's pin (`apps/web/src/__tests__/forge-briefs.test.ts`) reads that table
  and asserts the **live working tree** still holds amber at each cited line.
  Its sibling test in the same file measures at `d343300` instead.
- WI-071's change does the one thing the brief's own "Under Forge" column says
  it should: it takes the amber off eight of the ten sites and splits the
  ninth. `docs/panel-accent.md` is the new inventory.
- The pin landed on `main` **after** WI-071 forked, so WI-071 was green on its
  own branch and the collision only exists now.

The pin is **Probe's file** (`**/*.test.ts` is Probe's, per FACTORY.md), and
this item is Cog's. The fix was not folded in, for three measured reasons:

1. Re-anchoring the assertion to `d343300` — the pattern the rest of that file
   already uses — would make it `skipIf(!measuredCommitReachable)`, and CI
   checks out with the default depth of one, so **the check would stop running
   in CI entirely**. That is a weakened gate, not a fixed one.
2. Inverting the assertion to "these sites no longer hold amber" would be
   authoring the check that accepts this item's own work.
3. `prototypes/briefs/02-material.md` is the direction's record, and WI-071
   says in its own words that the brief files are out of its scope.

**Probe owns the resolution.** The likely shape is to keep the live-tree
assertion and re-state it as what the rule now says — that the ten sites the
brief names are the sites the accent rule claims — which is a stronger pin than
the one it replaces, and it is Probe's to write.
