## The judgement calls the guard asked for

The guard failed on the merged tree, as it was meant to. Two modules were
nobody's: `autonomy` (added by WI-082) and `measures` (added by WI-020). Three
violations came with them.

### `autonomy` → **Work**

The policy says what work may proceed. It is attached to a workspace and a
goal, and the goal's policy is Work's own row. `docs/domains.md` already named
"autonomy policy" under Work before the module existed, so the machine map and
the human copy agree.

The module imports no other module and writes no table, so classifying it
settles all three violations at once: the capability API may read across every
domain, and the audit trail is Substrate, which every domain may use.

**It does cross, and the crossing is declared.** The effective policy is
composed from a workspace's, a goal's **and a conversation's** policy. The
workspace's row is Substrate's (allowed), the goal's row is Work's own (own
domain), and the conversation's limits are Interaction's — so Work reads
Interaction's `conversations` row to finish the composition. The map's third
rule says nothing else may reach across, and a crossing that is genuinely
necessary is declared with a reason and the work item that removes it.

The manifest had no form for a read: `declaredCrossings` is for module
imports and requires a live import to stay honest, and `sharedTableWrites` is
for writes. **`sharedTableReads` was added with the same shape** — module,
table, owner, reason, work item — and the guard gained a case that checks it
exactly as the write case is checked: a real table, the domain that owns it, a
module that exists, and a work item. **A rule nothing verifies is a claim**, so
the read is declared _and_ checked for its shape.

The work item that removes it is **WI-110**: the capability API is the one
module allowed to read across, so it reads the conversation's limits and hands
them to the resolver, which stops reaching for the row itself. WI-059 removes
the Resources → Work crossing the same way.

### `measures` → **Resources**

The product's two measures are counted from what the product already keeps: the
authorship a resource carries, and the entries the audit trail holds. The audit
trail is Substrate, which every domain may use, so the module's only other
dependency is the resource store — which Resources owns. Putting it in Work or
in Substrate would have created a crossing that buys nothing, and the guard
would have refused the import.
