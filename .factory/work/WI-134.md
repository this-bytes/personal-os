# WI-134 — The domain does not depend on the adapters package

**Numbered:** 2026-10-22 — **WI-134**, read immediately before it was taken: the published
number block in `.factory/INTAKE.md` read "**The next free number is WI-134.**"

**Owner:** worker, under Chief.
**Verifier:** a verifier who wrote none of this.

**The claim is published before the work is done.** The block's row and this file land on
`main` in a commit of their own, so the next session that reads `main` sees WI-134 taken.
**That is the claim-first discipline used three times now — WI-129, WI-133 and this — and
it has not collided once.**

## The gap

**The rule is written in two places and enforced in neither.**

`AGENTS.md` rule 3: _"Do not introduce dependencies on one particular agent provider into
core domain logic. **The domain must not know that Hermes, Codex or OpenClaw exist.**"_

`docs/decisions/0004-adapter-registry.md:39`: _"**The domain never mentions a specific
provider.** 'Hermes' and 'Codex' are configuration, not code."_

Both are true of the tree today. **What is missing is the thing that keeps them true.**

The domain has exactly **one** dependency edge on the adapters package, and it is the
wrong kind of edge:

```ts
// apps/server/src/modules/agents/service.ts:13
import type { AdapterRegistry } from '@personal-os/agent-adapters';
```

**It is type-only, so it compiles to nothing.** But the type it names is the **class** from
the package that holds every concrete adapter — `packages/agent-adapters/src/index.ts:15-21`
exports the ACP, A2A, CLI, echo, HTTP, MCP and model adapters, and `:27` exports
`createDefaultRegistry`. **The whole barrel is one import away, and the compiler does not
distinguish "I want the class" from "I want its type".** Deleting the word `type` would put
every adapter inside the domain and nothing would complain.

**A word is not a boundary.** The only thing standing between the domain and the adapters
is five characters of import syntax that no gate, no type and no test looks at.

## The dead edge, and what it says

`apps/worker/package.json:16` declares `@personal-os/agent-adapters` as a dependency, and
**no file under `apps/worker/src` imports it.** The worker reaches adapters through the
server's runtime — `apps/worker/src/executor.ts:412`, `:842` and `:1073` all call
`runtime.registry.create(...)` — and `apps/server/src/runtime.ts:16` types that field as
`AdapterRegistry`, the class from the adapters package.

**So the worker's dependency is not merely unused: it is what makes the adapters package's
types resolvable in a clean install.** The worker needs a package it does not import,
because the server's public surface names a class that package owns. **That is the
coupling, seen from the other side**, and it is why removing the worker's dependency is
not a tidy-up but the proof that the edge is gone.

## What is not broken, and is worth saying

This item is about a boundary, not about a bug, so the things that are already right are
part of the record:

- **The domain does not name a provider.** The only occurrences of "Hermes", "Codex" or
  "OpenClaw" under `apps/server/src/modules` are in
  `conversations/__tests__/routing.test.ts`, as the display names of fixtures that exercise
  mention routing. **That is configuration, not code — exactly what ADR 0004 allows.**
- **Adding a new adapter type does not touch the domain.** A new type means
  `adapterTypeSchema` and its labels (`packages/contracts/src/agent.ts:9`), a config schema
  in `adapter-config.ts`, a new file in the adapters package, and one line in
  `createDefaultRegistry`. **The domain, conversation storage and the factory task model
  are untouched — which is the constraint ADR 0004 says keeps the boundary honest, and it
  holds.**
- **The worker already does the right thing**: it never imports the adapters package.

**So the rule holds. What is missing is the thing that keeps it holding.**

## The fix

**The shapes the domain needs move into the package the domain already owns.**

`packages/contracts/src/agent.ts` already holds `AgentAdapter` (`:244`) — the adapter
interface itself. The two shapes beside it are the rest of the adapter boundary
vocabulary, and they belong with it:

- `AdapterLogger` — what an adapter may say (`packages/agent-adapters/src/types.ts:3-7`)
- `AdapterContext` — what the server hands an adapter (`types.ts:13-16`)
- and a name for the registry's **shape**, so the domain depends on a capability rather
  than on a class: `AdapterProvider`.

`packages/agent-adapters` keeps the class and implements the shape. **The domain imports
the shape from `@personal-os/contracts`, and the domain's dependency edge on the adapters
package goes to zero.**

**And then the worker's dependency becomes removable**, because `Runtime.registry` names
the shape rather than the class. The worker already talks to adapters only through the
server's runtime; **this makes that true of its types as well as its code.**

The name follows the repository's own vocabulary: the resources module already has a
`ResourceProvider` — a per-kind thing that validates and creates — so `AdapterProvider` is
the same idea on the other side of the boundary.

## The check

**A rule nothing checks is a wish.** The repository has already turned three such wishes
into checks — the contract-status gate, the contract-pointer gate, and the licence
record's pin — and this is the fourth.

The check walks the source tree the way `apps/worker/src/__tests__/autonomy-policy-attack.test.ts:421-463`
already does — recursively, skipping `__tests__`, with an allow-list — and asserts that
the list of offenders is empty:

- no file under `apps/server/src/modules/**` imports `@personal-os/agent-adapters`
- no file under `apps/worker/src/**` imports it either
- `apps/worker/package.json` does not declare it
- **the only file in the shipped code that names the package is the composition root** —
  `apps/server/src/runtime.ts`, which is where the registry is built. The sweep covers
  the browser client and the UI package as well as the domain, **because the CLI adapter
  spawns a process** and a client that reached the adapters package would carry it into
  the bundle.

## The limitations, stated plainly

- **The check proves the edge, not the absence of a name.** It reads the source tree, so a
  domain module that branched on a provider's _name_ would not be seen by it. **What it
  does prove is that the domain cannot reach an adapter** without going through the
  boundary. The name-level rule is left to review, and this item does not pretend to
  enforce it.
- **The check is a test file, and the repository gives test files to Probe.** This session
  wrote it because the item could not land without it, and it is a new file with a new
  name, so nothing of Probe's is touched. **Probe may take it over.**
- **Moving a published shape between packages is a contract change.** `CONTRACTS.md` gets
  the new shapes, the rule they carry, and a migration note, in the same landing.

## The proof

- **The edge is measured before and after.** Before: one import in the domain, one dead
  dependency in the worker. After: none of either, and the check fails if either comes
  back.
- **The check is proved able to fail.** Three mutations, each restored byte for byte:

  | Mutation                                        | Cases that go red                                    |
  | ----------------------------------------------- | ---------------------------------------------------- |
  | the domain imports the adapters package again   | 2 — the domain check, and the composition-root check |
  | the worker declares the dependency again        | 1 — the worker's check                               |
  | the browser client imports the adapters package | 1 — the composition-root check                       |

- **The third mutation found a hole in the check itself, and that is the reason it is
  worth having.** The check walked the tree for `.ts` files, and the browser client is
  `.tsx` — **so the client was never inspected at all**, and the mutation that put the
  adapters package into `apps/web/src/main.tsx` turned **nothing** red. The walk now
  collects `.tsx` as well, and the same mutation turns the check red. **A check that has
  never been given a mutation it can fail is not a check.**
- **Nothing else moves.** The adapter package's own tests keep passing, the server's
  suite keeps passing, and the worker's suite keeps passing — the worker's
  `runtime.registry.create(...)` calls are unchanged, because the shape they use is the
  shape they had.
