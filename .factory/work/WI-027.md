## The problem

The waiting list is drawn from two things: pending approvals, and tasks. A
turn is neither.

An agent turn that runs out of time is recorded as `unknown` on the message
and on the execution — the worker's own suite proves those exact rows. The
contract says the owner sees an unknown item as "check this" and that only the
owner can close it. That is met for tasks. For turns:

- the owner is never told, and
- nothing can close it either — the only server writes to a message status are
  the approval reply and the execution resolution, and neither touches an
  unknown item.

So the most ordinary unknown of all is invisible, and it is invisible
permanently.

A red test pins it. `apps/server/src/__tests__/unknown-outcome.test.ts`,
"reaches the owner when it is a turn, not only when it is a task", inserts an
execution and a message with `status: 'unknown'` and asserts the waiting list
returns an item for that conversation with `reason: 'unknown'`. It fails
today.
