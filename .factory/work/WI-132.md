## The gap

## What this item does

1. **The waiting shape is published once.** The kind union, the reason union and the item
   move into `@personal-os/contracts`; the server's `apps/server/src/api/waiting.ts` uses

   and imports the published one.** **The fourth kind and `toolName` then arrive by
   construction, not by remembering.**
2. **The row says what it is.** The kind has a name of its own in the panel, rather than
   falling through to "Blocked".
3. **The row carries the action.** The owner widens the grant **from the row**, through the
   published route `POST /api/agents/:id/grants` with the row's `toolName`.

## The lead's ruling — 2026-10-22: the field is always on the wire

**Ruling: tighten the published declaration.** `packages/contracts/src/waiting.ts`
types `toolName` as `toolName?: string | null;` — optional. The contract
publishes the wire shape as `toolName: string | null`: the route always sends
the field, and `null` says the kind is not named by a tool. **An optional
declaration cannot hold that claim.** A field the type allows to be missing is
a field the server may stop sending with nothing — no type, no test, no gate —
noticing; the contract's sentence then describes a wire the type does not
promise. The declaration becomes:

```ts
toolName: string | null;
```

**`null` is not the same as absent.** `null` means the kind is not named by a
tool — a task or a turn has no tool to name. Absent means the client cannot say
anything about the field at all. **A client that builds a row of its own writes
`toolName: null` rather than leaving it out**, and the tightened declaration is
what makes the difference visible: a client that leaves it out is now a type
error, rather than a shape the server never sent and nobody noticed.

**This supersedes the paragraph above.** The implementation's earlier note said
the declaration is optional so a client can build a row without naming a tool it
does not have, and that the two fixture files were left alone. **Both halves
are now false, and this ruling replaces them:** the declaration is tightened,
and the fixture files are no longer left alone — they are the evidence.

**The evidence: Probe's five hand-built rows.** Every row built by hand in the
tree already writes the field:

- `apps/web/src/__tests__/accentGuard.test.tsx:89`, `:101`, `:113`, `:125` — four rows;
- `apps/web/src/components/__tests__/WaitingListPersona.test.tsx:101` — one row, built by the `item()` helper.

**Five rows, five `toolName: null`, none omitted.** The optional declaration
permitted leaving the field out; **not one of the five rows needed that.** The
tightening therefore takes nothing away from a client that builds a row: what
the optional declaration bought was never used, and what it cost was a wire
claim the type did not make.

**The witness commit.** The tightened declaration is `a9f7066` — single-parent

## The seven drift proofs — Cog, 2026-10-22

Each drift was measured on the branch tree by mutating the real file, running
the three nets, and restoring the file afterwards. **Every restore was verified
three ways: `git diff` empty, the on-disk blob equal to the index blob, the
tree blob and the baseline blob, and `git status` clean.** The three nets are
**the case** (Probe's `apps/web/src/__tests__/waitingCapability.test.ts`,
twelve cases), **the typecheck** (`npm run typecheck`), and **the contract
gate** (`npm run verify:contracts`, which checks the tree against

- **(a)** The kind union loses `'capability'`. The case _the published kind

- **(e)** The panel's action leaves the published route (`/grants` to

- **(f)** The server's row stops naming the tool. **The typecheck goes red**

  waiting-list test is green, and the contract gate is green.
- **(g)** The contracts package stops publishing the module. The typecheck goes
  red with five TS2305s — the module has no exported member `WaitingItem`,
  `WaitingKind` or `WaitingReason`; the contract gate goes red on the export
  pattern. **The case stays green**: it reads the source file by path, and it
  imports the published shape with `import type`, which is erased before the
  test runs.

**Why the typecheck is green on (b) and (c), and what it holds instead.**
TypeScript's identity relation holds two structurally identical interfaces to
be the same type, so a copy that _looks_ the same is the same type as far as
`SameType` is concerned: the type-level half of the check cannot see a copy
that is identical. **A copy that has drifted is caught, and that is the drift
that matters.** With the web holding the stale shape — three kinds and an
optional `toolName` — the typecheck goes red at
`apps/web/src/__tests__/waitingCapability.test.ts:97` (`Type 'true' is not
assignable to type 'false'`, which is the `SameType` line) and at `:129` (the
fixture's `kind: 'capability'`). With the server holding a drifted copy the
typecheck goes red at `src/api/waiting.ts:141`. **So the typecheck holds the
copy that has drifted, the regex case holds the copy that exists, and the
contract gate holds both.**

**The tightening is what makes (f) a type error — measured.** The same tree,
the same drift, with the declaration put back to `toolName?: string | null;`
and the server's row still missing its `toolName`: **the case, the typecheck
and the contract gate all stayed green. Nothing caught it.** Under the tightened
declaration the typecheck goes red. **A server that stops sending the field is
caught by the typecheck, and under the old optional declaration nothing caught
it at all.** That is the whole of the tightening's value, measured rather than
asserted.

**One thing the tightening does not reach, reported and not edited.**
`apps/web/e2e/waiting-list.spec.ts:47` builds a row by hand and **leaves
`toolName` out** — it is the sixth hand-built row in the tree, and the only one
that omits the field. **It is not caught:** the row is passed to
`serveWaitingList(page, items: unknown[])`, so no declaration constrains it,
and a row that is not typed as `WaitingItem` is outside the type system's
reach. **The file is Probe's, so it is reported rather than edited.** It is a
mock payload and not a client row, so the published claim stands as written;
but a lead who wants the field to be unavoidable everywhere should have Probe
type that fixture as `WaitingItem`, or give it `toolName: null` the way the
other five rows have it.
