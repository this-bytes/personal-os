## The gap

**The web client re-declares the shape the server publishes, and it is behind.**

- `apps/web/src/lib/types.ts:100` declares `kind: 'approval' | 'task' | 'turn'`, and the
  interface ends at `:113` with **no `toolName`**.
- The server publishes `kind: 'capability'` and `toolName`
  (`apps/server/src/api/waiting.ts:8` and `:42`).
- The row **renders safely today**: `labelFor` (`apps/web/src/components/WaitingList.tsx:393`)
  falls through to "Blocked", and the row already names the agent from `agentConnectionId`.
  **So this is not a crash — it is a client that no longer describes what the server sends.**
- The contract's migration note says _"a client that matched on three kinds has a fourth
  case to handle"_; **the web is that client.**
- And the row carries **no action**: the owner who sees a blocked capability is told what is
  blocked and sent to `/agents` to find the grant.

**And the drift is structural, not a slip.** The waiting shape is published by the **server**
(`apps/server/src/api/waiting.ts`), and the contracts package publishes nothing about it —
`grep Waiting packages/contracts/src` returns **no matches**. The web package _does_ depend
on `@personal-os/contracts` and already imports types from it, **so the one-declaration
fix is available.** As it stands the client can drift again, and this item is not satisfied
by remembering to add a field.

## What this item does

1. **The waiting shape is published once.** The kind union, the reason union and the item
   move into `@personal-os/contracts`; the server's `apps/server/src/api/waiting.ts` uses
   that declaration instead of its own, and `apps/web/src/lib/types.ts` **deletes its copy
   and imports the published one.** **The fourth kind and `toolName` then arrive by
   construction, not by remembering.**
2. **The row says what it is.** The kind has a name of its own in the panel, rather than
   falling through to "Blocked".
3. **The row carries the action.** The owner widens the grant **from the row**, through the
   published route `POST /api/agents/:id/grants` with the row's `toolName`.

## The contract changes

- The contract publishes that the waiting shape is the contracts package's declaration, so
  there is one published shape and the client cannot describe a different one.
- The waiting-list entry names the fourth kind's action.
- A claim-table entry (`scripts/contract-status.json`) so the status gate **checks** the new
  published shape instead of reporting it unchecked.
- A migration note: a client that matched on three kinds now has a fourth case to handle —
  **and the published shape moved, so a client that copied the old declaration must import
  the new one.**

## The proof

`apps/web/src/__tests__/waitingCapability.test.ts` — **Probe's file, named here and not
written by the owner.** The cases:

- the capability row renders with the kind's own name, not "Blocked";
- the row shows which tool the agent wanted, from `toolName`;
- the row's action calls the published route with the row's own `toolName`;
- **the client's shape IS the published shape** — a check that fails if the web re-declares
  the type instead of importing it, so the drift cannot come back;
- the other three kinds still render as they did.

`apps/web/e2e/**` is Probe's file as well, and the row's action is worth one end-to-end
case if the panel's e2e harness reaches the list.

## The names the implementation gave the lead's cases — Cog, 2026-10-22

The lead named the five cases above. The implementation gave them the concrete
names they are checked against, and these are what Probe's check must hold the
panel to. **The check file is still Probe's: `apps/web/src/__tests__/waitingCapability.test.ts`,
and `apps/web/e2e/**` is Probe's as well.\*\*

- **The kind's own name.** The capability row's badge reads **"Needs a grant"**
  (`apps/web/src/components/WaitingList.tsx:485`). It is not "Blocked": a
  capability carries the reason `pending`, so a label that went by the reason
  would file it under work that is stuck. The other three kinds keep their
  labels: "Approval", "In review" and "Check this", and a blocked task keeps
  "Blocked".
- **The tool the agent wanted.** The row shows **"Tool: `<toolName>`"** from the
  row's own `toolName` (`apps/web/src/components/WaitingList.tsx:342`), not out
  of the title, which is the server's sentence.
- **The row's action.** The row carries a button reading **"Grant the tool"**
  that posts to **`/agents/<agentConnectionId>/grants`** with the body
  **`{ tool: <toolName> }`** (`apps/web/src/components/WaitingList.tsx:181`).
  The route is the published `POST /api/agents/:id/grants`, and the `toolName`
  is the row's own.
- **The client's shape IS the published shape.** The declaration is
  `packages/contracts/src/waiting.ts`, and both sides read it: the server
  (`apps/server/src/api/waiting.ts:3`) and the panel
  (`apps/web/src/components/WaitingList.tsx:5`). **`apps/web/src/lib/types.ts`
  must not declare `WaitingItem` again** — it imports the published one and
  publishes it back out under the same name. A check that fails when the web
  re-declares the type is what keeps the drift from coming back.
- **The other three kinds still render as they did.** The kind union is closed
  at four members, and the label, the buttons and the link of an approval, a
  task and a turn are untouched by this item.

**One thing the implementation had to decide, and why.** The published
declaration types `toolName` as optional, and the contract publishes the wire
shape as `toolName: string | null` — the route always sends the field, and
`apps/server/src/__tests__/waiting-list.test.ts` checks the row field for
field against the published block. The declaration is optional so that a client
can build a row of its own without naming a tool it does not have. **The two
fixture files that build rows by hand — `apps/web/src/__tests__/accentGuard.test.tsx`
and `apps/web/src/components/__tests__/WaitingListPersona.test.tsx` — are
Probe's, and they were left alone.**
