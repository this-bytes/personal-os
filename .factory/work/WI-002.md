# WI-002 — Recover a forgotten owner password without an email service

**Owner:** Cog
**State:** verify
**Dispatched:** 2026-10-20, commit `161491f` (implementation, unverified)

## Problem

A Personal OS instance has exactly one owner, no email address to send a
reset link to, and no default credentials. If the owner forgets the password,
there is no way back in: the only recovery is to delete the database, which
takes every conversation, resource, task and goal with it.

The instance is meant to be handed to someone who is not the person who set it
up. That makes "I forgot the password" a normal state of a real deployment,
not a rare edge case.

## Why now

The implementation is already written and sitting in the working tree. It was
built without a work item, which is a doctrine failure in its own right: the
factory cannot accept, review or roll back code it has no record of. This item
gives that code a home, an owner and an acceptance test, and puts it in front
of the verifier before anyone relies on it.

## Acceptance criteria

- [ ] A forgotten password can be replaced on a running instance with no
      network, no email service and no access to the database.
- [ ] Replacing the password keeps every conversation, resource, task, goal
      and event. Nothing but the credential changes.
- [ ] Every session the old credential produced is signed out, and the old
      password stops working.
- [ ] The recovery path is not reachable over HTTP. No route may trigger it.
- [ ] Replacing the password does not expose the new password to other users
      of the host. If it does — a command-line argument is visible in the
      process table to anyone on the machine — then either the recovery path
      changes so that it does not, or the exposure is stated plainly in
      [CONTRACTS.md](../../CONTRACTS.md) and the [README](../../README.md).
- [ ] Running the deployment check never consumes the first-run setup slot, so
      that a verification run cannot hide the setup screen from the person
      using the instance.
- [ ] `npm run typecheck`, `npm run test`, `npm run format:check`,
      `npm run build`, `npx tsx scripts/smoke.ts` and
      `npx tsx scripts/verify-build.ts` pass.

## Not in scope

- No email, no SMTP, no password-reset token, no reset link.
- No second owner, no shared accounts, no roles.
- No change to the `POST /api/auth/setup` or `POST /api/auth/login` contract.
- No change to the deployment or Compose configuration.

## Gates

- `npm run typecheck`
- `npm run test`
- `npm run format:check`
- `npm run build`
- `npx tsx scripts/smoke.ts` ← the server changed
- `npx tsx scripts/verify-build.ts` ← the server changed

## Notes

The implementation, for whoever picks it up:

| File                                                    | What it does                                                        |
| ------------------------------------------------------- | ------------------------------------------------------------------- |
| `apps/server/src/modules/auth/service.ts`                | `resetOwnerPassword` — replaces the hash, deletes the sessions.     |
| `apps/server/src/index.ts`                              | A `--reset-password` mode on the server binary.                     |
| `scripts/reset-owner-password.ts`                       | The same thing from a checkout, by spawning the compiled server.    |
| `apps/server/src/__tests__/auth.test.ts`                | The tests for the service.                                          |
| `scripts/verify-deployment.sh`                          | No longer creates the owner account.                                 |
| `CONTRACTS.md`, `ARCHITECTURE.md`, `README.md`          | The documented behaviour.                                            |

**The question Probe should answer first.** A password passed as a command
line argument is visible in the process table to every other user on the
machine, and `CONTRACTS.md` documents exactly that form:
`node apps/server/dist/index.js --reset-password "<new password>"`. The
criterion above allows either a change or a plain statement of the exposure.
Which one is right is a judgement call, and it is Chief's — but it has to be
made deliberately rather than by omission.
