## The owner's answer, and the gap it names

**The owner's answer, 2026-10-21: add an `mcp` adapter type, so any MCP server
can be an agent connection.**

The gap: the factory's roles are bots in a MiniMax Bot team, and that team is
an **MCP server** — the `OFFICIAL/minimax-bot` plugin exposes 22 tools. Personal
OS's adapter registry knew `cli`, `acp`, `a2a`, `http`, `model` and `echo`, and
the server's own MCP module is a _server_: it exposes Personal OS outward. So
the instance had no published way to reach the roles it was about to dispatch
work to.

## Acceptance criteria

- [ ] **A connection to an MCP server is registered, dispatched to and
      answered, through the published adapter path**, with no change to
      conversation storage or the factory task model — the rule AGENTS.md
      states for every new adapter.
- [ ] **The adapter is a client of MCP, not a fork of it**: it initializes the
      session, lists the server's tools, and calls one of them for a turn. The
      server's own tool names and schemas are used as published.
- [ ] **The adapter claims only what it can do.** A tool call is atomic, so the
      adapter reports `cancel: false`, `streaming: false` and
      `acceptsSteering: false`, and a server that does not publish the
      configured tool reports `chat: false` rather than failing a turn at the
      moment the owner is waiting.
- [ ] **The server's environment does not leak into the agent's.** A supervised
      server process gets an explicit allow-list plus the values the owner
      configured — the same rule the `cli` adapter follows, and the same helper.
- [ ] **The configuration is held in `secret_configs` and its values never
      appear in a response**, and a bearer token is a reference, never a value.
- [ ] **The panel can register one**: the connection form carries the MCP
      fields, and the type appears in the adapter list.
- [ ] **No dependency is added.** The client speaks the published protocol over
      the JSON-RPC the repository already has; `package.json` and the lockfile
      are unchanged.
- [ ] **A test proves it against a real MCP server** — a separate process that
      speaks the protocol — rather than a mock of our own assumptions.
- [ ] `npm run typecheck`, `npm run test`, `npm run format:check` and
      `npm run build` pass.

## Notes

**One defect was found and fixed on the way, and it was not this item's own
code.** `JsonRpcStdioClient` did not handle the child process's `error` event,
so a command that could not be started left the request pending until it timed
out — a hang where a failure belonged. The client now rejects the pending
requests, and the adapter reports `chat: false` immediately. The same latent
fault was in the ACP and A2A adapters, which use the same client.
