## The problem

`docs/strategy.md` carries a table of the dependencies this product takes
inspiration from, and it has a licence column. **The licence column was read
from a directory listing rather than from the repository**, which is a
difference that matters: a directory listing shows that a licence file
exists, and not which licence it is.

The same gap is in the dependency set itself. The product depends on things,
and nothing in the repository says what their licences permit and what they
forbid.

## Acceptance criteria

- [ ] **Every dependency in the lockfile has a licence recorded**, and each
      entry is attributed to the file it was read from — the repository's
      `LICENSE`, the `license` field of its `package.json`, or the SPDX
      identifier the project publishes — rather than to a listing.
- [ ] **Each recorded licence says what it permits and what it forbids.** A
      licence name alone is not a licence record.
- [ ] **The AGPL question the owner raised is answered against the actual
      dependency set.** The owner asked whether anything in what this product
      depends on is AGPL. The answer names the dependencies and the licences
      that were actually read, and it is an answer about _this_ set, not a
      general statement about a category.
- [ ] **A note in the document says when the column was read**, so a reader
      knows how old the reading is.

## Notes

**Why the record comes before the gate.** WI-038 fails the build when a
licence changes or an unapproved licence appears. A gate that compares
against nothing catches nothing, and a gate that compares against a stale
table catches the wrong thing. The record is the ground truth; the gate is
the thing that watches it.

**What was read, and from where.** Each entry says which file it came from.
That is the difference between a licence and the name of a licence, and it is
the only reason a later reader can tell whether the reading is still true.
