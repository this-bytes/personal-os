## The owner's decision

The owner was asked one question:

> An agent turn that runs out of time is recorded as an unknown outcome — but
> it never reaches you. The waiting list's published kind only has 'approval'
> and 'task', so an unknown turn has nowhere to appear. The contract already
> promises that an unknown outcome reaches you as 'check this' and that only
> you can close it; for turns that promise is broken, and a broken turn can
> never be closed at all. Does the published kind grow by one, so an unknown
> turn reaches you too?

**Answered at 07:07 on 2026-10-21: yes.** The published kind grows by one, so
an unknown turn reaches the owner too.

## The problem

`CONTRACTS.md:640` publishes the waiting list's kind:

```ts
type WaitingKind = 'approval' | 'task';
```

There is no member for an agent turn. And a turn is not an approval and not a
task, so it cannot be spelled as either without the published type becoming a
lie in the other direction — a client that switches on the kind would have to
handle a turn wearing a task's name.

**The promise is already broken, and a broken turn can never be closed.** The
contract says an unknown outcome reaches the owner as something to check, and
that only the owner can close it. That is met for tasks today. For turns it is
not met at all: the owner is not told, and nothing can close it — the only
server writes to a message status are the approval reply and the execution
resolution, and neither touches an unknown item.

A red test pins this. `apps/server/src/__tests__/unknown-outcome.test.ts`,
"reaches the owner when it is a turn, not only when it is a task", inserts an
execution and a message with `status: 'unknown'` and asserts that the waiting
list returns an item for that conversation with `reason: 'unknown'`. It fails
today, and it is one of the deliberate reds standing between the tree and the
push the owner asked for.
