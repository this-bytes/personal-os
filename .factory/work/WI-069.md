# WI-069 — A delegation that names nobody is refused in a way a client cannot read

**Owner:** Cog (the code), with the contract half for Wren
**Verifier:** Probe
**State:** implement — **opened and numbered, and deliberately not dispatched.**
The finding is Probe's, from WI-021's verification: a delegation addressed to a
participant id that names **nobody** is refused with a generic reason and **no
`blocked` key**, so a client cannot tell that refusal from "there was nothing
to wake". **Two reasons it is held, and both are said out loud below.**
**Opened:** 2026-10-21 by Chief, from Probe's WI-021 verification
**Numbered:** 2026-10-21 — **WI-069**, taken by this session as the next number
above all of them, under the rule the number space publishes. WI-030 through
WI-038, WI-044, WI-045, WI-062, WI-065 through WI-068 are the number space
owner's; WI-024 through WI-029 and WI-039 through WI-043 are the other Chief
session's; WI-046 through WI-064 are the strategy session's. **If another
session has taken WI-069 in the meantime, this item is renumbered and the
table is corrected.**

## The finding, in Probe's words

> **Question for Chief — the same shape, one step further out.** A delegation
> addressed to a participant id that names **nobody** is refused with a generic
> reason and **no `blocked` key**, so a client cannot tell that refusal from
> "there was nothing to wake", and the reason does not admit that the named id
> matched nobody. Outside WI-021's five criteria (it is about a delegation
> addressed to a _participant_), but the same class the item is about — it may
> deserve its own item.

**Measured, not described.** The ids are filtered to enabled agent connections
at `apps/server/src/modules/conversations/routing.ts:131` before the refusal
is built, so a delegation naming an unknown id never reaches the branch that
names the target. What happens instead: the reason becomes _"An agent message
does not automatically trigger other participants in coordinator mode."_ and
`blocked` is undefined. **The refusal reads as a statement about agent
messages in general, not as a statement about the id the caller supplied.**

## Why this is not simply WI-021's business

**WI-021's criterion 3** is _"the reason string names the target that was
refused"_. Here there **is no target** — the id matched nobody — so the
criterion is not violated. And WI-021's criterion 1 says it plainly: _"changing
a published contract... needs the owner, a migration plan and a `CONTRACTS.md`
entry."_

**And there is no published contract for this.** **WI-021 has no entry in
`CONTRACTS.md` at all** — Probe checked, and the refusal's shape, its
`blocked` key and its wording are published nowhere. So a client cannot tell
the two refusals apart, and there is no published promise it is breaking.
**That is a gap in what the product says about itself, not a violation of
something it already said.**

## The question for the owner

**Should the product publish the shape of a delegation refusal, so that a
client can tell "you named an id that matched nobody" from "there was nothing
to wake"?**

Chief's recommendation: **yes, and in the smallest form** — a refusal that
names nobody says so, and carries a `blocked` key like the refusal that names
a target does. A client that cannot distinguish two different refusals cannot
write an error message that helps. **But this is a product decision and not
the lead's**, because publishing the refusal's shape is a contract change, and
a contract change is the owner's.

**The code half does not wait for that answer.** The code can say what
happened without the contract saying it — the reason string is already
product behaviour that a client reads in the panel. So the two halves can run
in parallel: Cog teaches the refusal to admit that the id matched nobody, and
Wren publishes the refusal's shape once the owner has said what it is.

## Acceptance criteria

- [ ] **A delegation that names an id matching no participant is refused, and
      the refusal says so.** It must not read as a general statement about
      agent messages, and it must not imply that something was woken.
- [ ] **The refusal carries a `blocked` key**, as the refusal that names a
      target does, so a client can branch on the reason rather than on the
      prose.
- [ ] **A delegation that names a participant still behaves exactly as it does
      today.** The change must not alter WI-021's refusal, its wording, or the
      `targets` array.
- [ ] **The contract publishes the refusal's shape** — the `blocked` key and
      what its values are — so that a client written against the contract can
      tell the refusals apart. **This half waits for the owner's answer.**
- [ ] **A test proves both halves** — a delegation naming a participant, and a
      delegation naming nobody — and **the test is Probe's to write**
      (`**/*.test.ts` is Probe's by the ownership table). It fails before the
      change and passes after.
- [ ] `npm run typecheck`, `npm run test`, `npm run format:check`,
      `npm run build` pass, and the tree is clean at the end.

## Not in scope
