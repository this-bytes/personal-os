## The gap

**The contract attributes the boundary to one gate, and the gate holds half of it.**

`CONTRACTS.md`, in the section "The adapter boundary", says:

> **The limit, stated plainly: this is about the dependency, not about the words.** The
> domain may name a provider in a fixture — that is configuration, and
> `docs/decisions/0004-adapter-registry.md` allows it. **What the check holds is that the
> domain cannot reach an adapter.**

And, in the bullet list above it:

> **So the domain cannot reach an adapter except through this boundary, and adding an
> adapter type does not touch it.**

**Probe reproduced the gap in the verifier's own hand.** The check
(`apps/server/src/__tests__/adapter-boundary.test.ts`) reads the tree and looks for the
package **name** — `@personal-os/agent-adapters`. A domain module mutated to reach the
adapters by a **relative path** instead — `../../../../packages/agent-adapters/src/...` —
left the check **3/3 green**. **`tsc` caught it** (TS2307, the module is not resolvable),
**so the boundary does hold** — **but it is held by two mechanisms, and the contract names
one of them.**

The gap is not the boundary. It is the sentence about which mechanism holds it. **A
published limit that names the wrong holder is a limit that is wrong the moment somebody
relies on it** — a client that reads the contract will believe the check is what stops a
relative-path import, and the day the compiler's path changes, the check will not be
there.

**The item file said the same thing**, in "The limitations, stated plainly":
_"What it does prove is that the domain cannot reach an adapter without going through the
boundary."_ That is the lead's own sentence, in the lead's own file, and it is corrected
there by append.

## What this item does

1. **The contract names both holders.** The check holds the **named edge** — nothing in the
   domain may import the package by name. The **compiler** holds every other import,
   because a relative path into the package is not resolvable and does not compile. The
   sentence says which is which.
2. **The limit is published, not implied.** The section already says the check is "about
   the dependency, not about the words" — **that half is right and stays.** What is added
   is the other half: the check does not see a relative path, and the compiler is what
   sees it.
3. **The check says its own limit.** The check file is **Probe's**, and a check that
   cannot see one way in should say so in its own failure message, so the next reader
   learns it from the tool and not from a report.
