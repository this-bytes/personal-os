# WI-152 — A steer goes into the turn that is running

**Owner:** the contract lane — the session that owns `CONTRACTS.md` while its
slices are in flight.
**Verifier:** Probe, who reviews the slice before it is accepted.
**State:** accepted — a steer goes into the turn that is running. It landed in
`main` at `cee9c69` and `CONTRACTS.md` publishes it: the delivery mode is
`packages/contracts/src/conversation.ts`, the rules are
`apps/server/src/modules/conversations/steer.ts`, and the channel that carries a
steer into the running turn is `apps/worker/src/steer.ts`. Closed under ADR 0012
on 2026-10-23.
**Branch:** none — the slice landed on `main`.
**Base:** `1e852e1`

## Problem

**Steering was published, routed, and did nothing.**

`CONTRACTS.md` publishes the delivery mode of a message, the `acceptsSteering`
capability, and the rule that a steer goes into the running turn's agent alone.
The code carried none of it:

- `apps/server/src/api/conversations.ts` — the route's body schema had no
  `delivery` field, so the mode was stripped before it reached the service;
- `apps/server/src/modules/conversations/service.ts` — every message was a
  queued message, and a queued message starts a turn of its own;
- `apps/server/src/modules/executions/activity.ts` — the run control said
  _"This server does not deliver messages into a running turn yet, so a steer
  would be queued instead"_, and `apps/server/src/api/executions.ts` computed
  `canSteer: false` for every turn;
- `apps/worker/src/executor.ts` — the turn ran the adapter with no way to
  receive anything the owner said while it ran;
- `packages/agent-adapters/src/echo.ts` — the adapter reported no steering
  capability, and there was no channel to read one from.

The contract said the degradation was reported rather than silent, and the
code did report it — the degradation was simply total.

## What changed

**The route reads the mode.** `POST /api/conversations/:id/messages` takes
`delivery: 'steer' | 'queue'`, and the answer says what happened to it: a steer
that could be delivered into a running turn was, and a steer that could not is
a queued message with the server's reason for it.

**A steer starts no turn of its own.** The rules are a pure function —
`apps/server/src/modules/conversations/steer.ts` — because a rule that needs a
database to be wrong is a rule that is hard to reason about. A steer names one
agent; the running turn of that agent takes it; nobody else is woken, and the
turn count does not move.

**The worker is the only thing that can put a steer into a running turn.**
`apps/worker/src/steer.ts` holds the channel and the feeder: the turn reads
the owner's messages from the channel while it runs, and each one is marked as
taken the moment it is handed over. A steer nobody took is not dropped — the
next turn takes it and the message says it was delivered late.

**The adapter is told what it can do.** `AgentTurnInput` carries an optional
`steer` channel, and only a connection that reported `acceptsSteering` is
given one. The echo adapter reports the capability and answers the last thing
it was told.

## The shape, and where it is

| What                                        | Where                                                      |
| ------------------------------------------- | ---------------------------------------------------------- |
| The delivery mode on the message            | `packages/contracts/src/conversation.ts`                   |
| The steering channel on the adapter's input | `packages/contracts/src/agent.ts`                          |
| The two columns a message carries           | `apps/server/src/db/schema.ts` (`delivery`, `consumed_at`) |

| The route that reads the mode               | `apps/server/src/api/conversations.ts`                     |

| The adapter that takes one                  | `packages/agent-adapters/src/echo.ts`                      |

## Scope and compatibility

**Owned paths** — the contracts, the schema and its migration, the
conversations module, the executions module, the worker, the echo adapter, the
chat client, and the contract.

**Compatibility.** The delivery mode is additive and defaults to `queue`: a
client that sends nothing behaves exactly as it did. A message written before
this existed is a queued message, and reads as one. The migration adds two
columns and rewrites nothing.

**What did not change.** A steer still does not wake other participants, does
not count as a new turn for the duplicate check, and does not weaken any of the
mandatory routing safeguards. The rules are the same rules, applied to a
message that asks for the running turn instead of the next one.

## Acceptance criteria

- [x] The route reads the mode, and the answer says what happened to it.
- [x] A steer goes into the running turn and starts no turn of its own.
- [x] A connection that cannot take input is not given a channel, and the
      degradation is reported.
- [x] An unconsumed steer is delivered to the next turn and recorded as late.
- [x] The browser suite proves it: the owner steers a running turn and the
      answer is the owner's steer.

## Not in scope

- **The capability view.** A turn's pinned view of its connection's
  capabilities is still absent, and the steering decision reads the
  connection's reported capabilities instead. That is a WI-055 item.
- **The five named runtimes.** None of them has run.
