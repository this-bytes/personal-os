## The problem

Two things the product does are not published.

**What "authored by an agent" counts as.** The contract says the product
reports the share of shipped features authored by agents inside the instance,
and it does not say what "authored by an agent" means. WI-020 publishes the
route that computes it, and WI-033 makes the underlying columns true, but
neither can answer the owner's question — _authored by an agent_ is a
definition, and the definition has to be written down before the code that
implements it is written.

**What an audit entry's outcome can be.** The audit trail records that
something happened. The set of outcomes an entry can carry — `queued`,
`succeeded`, `failed`, and whatever else the implementation needs — is
published nowhere, so a client cannot know what it is being told.

## Acceptance criteria

- [ ] **The entries land before the code ships.** This item is published
      first, and WI-033 implements what it publishes.
- [ ] **They match the code member for member.** The published outcome set is
      the one the code writes, checked against the implementation and not
      against a proposal.
- [ ] **The migration note says what a client written before the change does**
      — what it may assume, and what it must now check — **and what a record
      written before the change means.** A record written before the change
      has no outcome; the note says what such a record is.
- [ ] **Nothing is reclassified.** No existing record is rewritten to carry an
      outcome it did not have.
- [ ] The entries do not contradict the neighbours: the route table, the
      `executionOwner: 'external'` entry that nothing writes
      (`CONTRACTS.md:544`), or the waiting list's own entries.
