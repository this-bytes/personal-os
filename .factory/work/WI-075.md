## Chief's rulings, because the lead's call was asked for

**One: yes, a check should watch the implementation-status claim, and it
belongs in `published-shapes.test.ts`.** Probe's answer, and the lead agrees
with it — the file is where the other two claims about the code are watched,
and a third claim watched elsewhere is a claim that is watched once.

**Two: the narrow form is the must-have, and it is scoped to the section that
was false.** `contractsSection('### The template record')` — the section
`published-shapes.test.ts` already reads. **The detection is reliable there**,
because the section is one named block.

**Three: the general form is wanted, and the list of open items is defined.**
The general rule Probe proposed is better: _every status sentence must either
name a commit or name an item that is still open._ **Chief's ruling on the
list the general form needs:** an item is **open** when its file's `**State:**`
line does not begin with `accepted` — every file in `.factory/work/` carries
one, and the accepted ones are exactly the ones whose line begins `accepted`.
**The general form's hard half is not the list. It is the detection** — finding
a status sentence anywhere in a document of prose is a prose problem, and that
is why the narrow form comes first. **So: do the narrow form certainly; do the
general form if you can find a detection you trust, and if you cannot, say so
in your report and the narrow form stands alone.** That is a judgement about
reliability, and it is Probe's to make.

**Four: the check may not make `main` red, and the order is fixed.** Probe
measured that the check is red on `main` until WI-065's correction lands —
`CONTRACTS.md:578-586` is still false today. **A red gate on `main` is not
acceptable.** So: **write the check on its own branch; do not merge it, and do
not push it, until WI-065's correction has landed** (Wren's task
`task_6274afe1abc1`). **A branch that is red waits a second round, and a branch
that is not pushed never reaches CI.** Chief merges it when the correction is
in.

## Acceptance criteria

- [ ] **`published-shapes.test.ts` watches the implementation-status claim** in
      the section it already reads. It asserts that the section publishes no
      unimplemented-status sentence, and that it names the implementing commit
      in the form the corrected entries already use — _"the code implements it
      — as of `<commit>`"_ (`CONTRACTS.md:909-910`).
- [ ] **The strong form of the check is there too**: the named commit is in
      the tree (`git rev-parse --verify`), so a status sentence naming a commit
      that was never pushed is caught.
- [ ] **The general form is attempted if a reliable detection exists**, using
      the lead's definition of an open item: **its file's state line does not
      begin with `accepted`.** **If no reliable detection exists, the report
      says so and the narrow form stands alone** — a half-reliable check that
      needs constant adjusting is worse than no check, because it teaches people
      to edit the check.
- [ ] **The check is proved to bite.** Removing or falsifying the status
      sentence's commit must turn it red, and the failure must name the
      section and the sentence. **A check that has never been seen to fail is a
      check that cannot fail.**
- [ ] **Nothing else in `published-shapes.test.ts` changes.** The kind enum
      and the route counts it already watches keep watching, and their
      assertions are not loosened. **The counts it publishes stay honest** —
      35 mutating routes and 21 route-level audit entries — and any route
      added here is counted correctly.
- [ ] **The check does not land on `main` before WI-065's correction has.**
      Report the state plainly: written, and not merged, and why.
- [ ] `npm run typecheck`, `npm run test`, `npm run format:check`,
      `npm run build` pass on the branch, and the tree is clean at the end.

## Not in scope

- **`CONTRACTS.md` itself.** The check is Probe's; the correction is Wren's
  (WI-065, `task_6274afe1abc1`). **Do not edit the contract.**
- **WI-031's stale status note** at `CONTRACTS.md:197-204`. That correction is
  dispatched (`task_be25e082ae5c`), and it is the same class of sentence — so
  **if the general form exists, it covers that entry too, and if it does not,
  that entry is corrected by hand and stays correct.**
- **The citation class.** The four stale citations in the measures section and
  the three in the waiting list are **a different class**: a pointer that no
  longer points at the line that carries its claim. **This item does not close
  that gap and does not pretend to.** A citation watcher would have to know
  what a citation _claims_, which is a harder problem than knowing that a
  sentence says "not implemented", and it is **named here so that it is not
  lost**: it has now bitten twice (WI-022's waiting-list refresh, WI-036's
  measures refresh), and both times it was found by a verifier rather than by a
  check.
- **The rest of the published-shapes file.** The two claims it already watches
  are watched well.
