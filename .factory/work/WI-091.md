## The problem

The contract leads the code — and when the code lands, the contract's note has
to follow. **Nothing asks it to.**

The candidate list names it as **C-23**, and it already has two instances:

- The template record said _"the code does not implement it yet"_ after WI-017
  landed (`363428e` at 11:05 → `414996c` at 11:32).
- The resolve route's entry was true when it was written and false 27 minutes
  later.

They did not drift at the same rate — one went false in 27 minutes, the other
took four hours and fifteen minutes. **A published count was caught by the
pipeline, but a stale _status_ is not a count, and no test can fail on it.**

WI-083 sweeps the stale notes that exist today. **This item makes the sweep
unnecessary tomorrow.** Without it, the ledger's "documented gaps" come back,
and a stale "gap" is an invitation to rebuild something that already exists —
which is how 2026-10-21 produced 380 commits and very little product.

## What this item does

A script, in the shape of WI-038's borrow-rule gate, that reads
`CONTRACTS.md` and checks every **implementation-status note** against the
code, and fails when a note no longer matches the tree.

## The hard part, stated plainly

A status note is prose. "The code does not implement it yet" is a claim about
the absence of a route, a function, a field, or an event. **There is no
general way to check prose against code.** So the gate must not try to be
general.

The design that works:

1. **A machine-readable marker.** Each checkable status note carries a stable
   identifier — a contract anchor, a route path, a symbol name, an event name
   — that the note refers to. The note's _claim_ is one of a small closed set:
   `not-implemented`, `partial`, `implemented`.
2. **A table of claims.** The script holds the claims it can check, each
   pointing at a file, a symbol or a route, and what the tree must contain for
   the claim to be true. A claim is checked by **absence** for
   `not-implemented` (the thing is not there) and by **presence** for
   `implemented`.
3. **A note the script cannot check is not a failure.** It is reported as
   unchecked. The gate never guesses, and never blocks on prose it cannot
   read.
4. **The drift is found by the writer, not by the reader.** The claim table
   says what to look for; a note that changes its claim has to change the
   table entry too, in the same commit. **That is the point: the contract and
   its status can no longer move apart.**

## The rules

1. **The script never edits a contract.** It reads and it fails. Correcting a
   false note is a human decision with a `CONTRACTS.md` update, and a contract
   change needs the owner.
2. **It never guesses.** A claim it cannot check is reported, not failed.
3. **It is a gate, not a linter.** It exits non-zero, and CI runs it — in the
   same job as the borrow-rule gate, or its own job. `npm run verify:contracts`
   is the script name.
4. **The check must fail on a real drift.** Prove it: introduce a drift in a
   scratch copy — a note that says `not-implemented` for something the tree
   does implement — and show the script catching it. A gate that has never
   failed has not been tested.
5. **The check must pass on the tree as it stands**, apart from the notes
   WI-083 is correcting in parallel. If the tree has a genuine drift, report
   it — do not paper over it by weakening the check.

## Acceptance criteria

- [ ] `scripts/verify-contract-status.ts` exists and runs as
      `npm run verify:contracts`.
- [ ] It reads `CONTRACTS.md`, finds every implementation-status note carrying
      a checkable marker, and checks each against the tree.
- [ ] A false note fails the script, with the note, the file and the line, and
      the claim that was expected.
- [ ] An uncheckable note is reported as unchecked and does **not** fail the
      run.
- [ ] The drift test: a deliberately false note in a scratch copy is caught.
      The output is in the report.
- [ ] CI runs it, and CI is green on the branch.
- [ ] `npm run typecheck`, `npm run test` and `npm run format:check` pass.
