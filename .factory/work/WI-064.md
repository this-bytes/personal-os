## WI-064 — The plan the free period is spent on, and the roadmap that outlives it

**Owner:** Wren
**State:** implement

### Problem

The owner has three to four days of unlimited MiniMax Code, and wants them
spent on a project that ends in a well-put-together state, with a long-term
roadmap, and with a structure agents can adapt to and work on by themselves.

Measured on 2026-10-21, the tree is green — every gate passes on `main` — but
the factory's own ledger records 104 `BUSY` / `AGENT_UNAVAILABLE` / cancelled
/ unassignable dispatches, and the work that did land got there through a
session turn rather than through the dispatcher. The number space is split
across three sessions and one number was allocated twice. The queue is
readable by a person and not by a program. The repository is private and this
machine has no GitHub token, so CI's verdict cannot be read here.

The scarce resource during the window is therefore not model capacity. It is
coordination capacity, and nothing on disk says so.

Two documents are missing as a result: a plan for the window that names the
work, the lanes, the order and the gates, and a roadmap that says where the
product goes and why, for an owner deciding what to build and for an agent
arriving with no memory of any of it.

### Why now

Because the window is the only period where this work is cheap. The plan
itself is the thing that makes the window produce landed, verified work
rather than a larger queue.

It also unblocks the four-day run itself: the plan's Day 1 _is_ the pipeline
work — a machine-readable queue, a dispatcher that records its failures, one
number space, a readable CI verdict — and those are the items that make
unattended round-the-clock work possible at all.

- [ ] `docs/free-period-plan.md` exists, names the lanes, the day-by-day order, the acceptance criteria per item, and the things the plan deliberately does not do.
- [ ] `docs/roadmap.md` exists, names the five domains, states the order of the four horizons with the reason that order is forced, and tells a fresh agent how to start.
- [ ] Both documents state the measured facts they rest on, and each such fact is checkable against the repository.
- [ ] Both documents state what the free period actually is — quota, not throughput; rate limits are separate from quota — and are consistent with MiniMax's published usage rules.
- [ ] The plan records the MCP workspace-scoping defect as a named item rather than leaving it in a plan nobody executes.
- [ ] The plan records the `wi/046-domains-interaction-model` branch as verified and landable, names its two major findings, and says the merge is a tiebreak that must be said out loud.
- [ ] No published contract is changed by this item.
- [ ] `npm run format:check` passes.
