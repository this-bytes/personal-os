# WI-050 — The MiniMax Code licence, read from the repository

**Owner:** Wren
**Verifier:** Probe

repositories.
**Opened:** 2026-10-21 by the strategy session, from the owner's answer on the

**Numbered:** 2026-10-21 — WI-046 through WI-061, taken by the session that owns
the number space.

## The owner's answer, and the gap it names

**The owner's answer, 2026-10-21: read and reimplement against our contracts,
attribute anything carried over, zero runtime dependencies.**

The gap: the landscape table in `docs/strategy.md` records the licence of every
comparator read from its repository, and MiniMax Code was not in it — even
though it is the project the owner named as the foundation for the interaction
design, and even though its licence is the one that permits a great deal.

## Acceptance criteria

- [ ] **MiniMax Code is a row in the landscape table**, with the licence read
      from the repository and not from a directory listing, and the row says
      what we took and where it lands.
- [ ] **The row carries both facts, and the second is the one that matters:**
      the CLI and harness are MIT — first-party code defaults to MIT,
      `third_party/sandbox-runtime` is Apache-2.0, and the Pi-derived terminal
      code, the model catalog and the bundled assets keep their own declarations
      — and **the desktop application is not published at all**.
- [ ] **The record says what "not published" forbids**: the desktop experience
      can be read, observed and recreated, and there is no code to copy from
      it. This is a licence fact of the same kind as n8n's Sustainable Use.
- [ ] **The row is dated**, because this is the first row whose boundary moves
      with an upstream release. The date is 2026-10-21.
- [ ] **PRODUCT.md §10 carries the note**: what was reimplemented, that no
      dependency was added, and that `package.json` and the lockfile are
      unchanged by any of it.
- [ ] **The attribution rule is written down**: where an implementation is
      carried over rather than rewritten, the file names the upstream project,
      the upstream file and the upstream licence.

## Not in scope

## Notes

The upstream repository publishes a `release/dependency-licenses.json` that
records its dependencies' declared licences. It is a useful precedent for what
the record looks like, and it is not copied — the record is ours, and it is
about the projects we read rather than the ones we depend on.
