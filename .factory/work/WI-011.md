## Problem

The product's identity was decided on 2026-10-20 in a strategy session with the
owner, and it is not written down anywhere. `PRODUCT.md` still opens with
"Personal OS is an agent-native control panel and personal software factory" —
which is the _factory_ half of the product, not the whole of it.

The owner settled these, and the repo is where a decision lives:

- **Identity.** Personal OS is an environment that one person's agents operate
  and extend. Agents do the work; the owner holds the authority.
- **The human's role.** The owner directs, approves and accepts. Agents do
  everything else. The one exception is connecting a new agent, which is a
  trust decision rather than a decision.
- **Agent-created features.** Typed native resources, authored through
  templates, sharing one resource API.
- **Everyday productivity.** Tasks/work and documents. Not email, not
  calendar.
- **The measure.** The share of shipped features authored by agents inside the
  instance, and the share of routine operations completed without the owner
  touching code.
- **Borrowing.** Other projects are inspiration. We implement against our own
  spec; we do not vendor and we do not depend. Interfaces are conformed to,
  never forked.

## The sweep that sharpened the strategy

Twelve comparators, licences read from the repositories themselves
([`prototypes/DIRECTION.md`](../../prototypes/DIRECTION.md) and the sweep it
comes from). Three findings change what has to be written down. They are
findings, not decisions — the owner has not ratified them.

1. **There is a forming standard for the extension surface, and it carries our
   authority model.** The MCP Apps extension (SEP-1865, proposed 2025-11-21 by
   MCP core maintainers at OpenAI and Anthropic with the MCP-UI creators)
   lets a server ship UI to a host: pre-declared `ui://` templates the host
   can review before execution, communication over plain MCP JSON-RPC so it
   stays auditable, sandboxed iframes, and hosts able to require explicit
   approval for UI-initiated tool calls
   ([post](https://blog.modelcontextprotocol.io/posts/2025-11-21-mcp-apps/)). It
   is a _proposal_, not a ratified standard, and it requires a text-only
   fallback. The host's approval gate is the part that matters to us: it is
   the same shape as "the human decides", and it is the same shape as our own
   ledger. So "native" should mean typed in our contracts _and_ rendered
   through that mechanism, rather than a surface we invent.
2. **Both working precedents of agent self-extension succeed for one reason:**
   a mandatory check before the artefact counts. Anthropic's skill-creator
   authors new skills under a typed contract with evals
   ([skill](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md));
   n8n's MCP server creates real workflows and its own rule is
   validate-before-deploy, copy-before-edit
   ([n8n-mcp](https://github.com/czlonkowski/n8n-mcp)). Our ledger — goal →
   task → execution → evidence → acceptance — is that shape already. The rule
   to write down: _an agent-authored artefact does not exist until something
   has checked it._
3. **The licence reality is why the borrow rule is right.** n8n is Sustainable
   Use, and its licence file says it is "not licensed under any of the main
   open source licenses"; Dify is a modified Apache 2.0 with additional
   conditions. Both are verified in the repositories themselves. A licence can
   change what the product is, which is exactly what the owner's Q5 answer
   refuses. And there is one hard case the owner must decide rather than the
   factory: **vendoring AGPL-3.0 code into this repository changes this
   project's licence.**

## Acceptance criteria

- [ ] `PRODUCT.md` opens with the settled identity in the owner's terms, and
      the factory is described as a part of the product rather than the whole
      of it.
- [ ] `PRODUCT.md` states the human's role — direct, approve, accept — and the
      agent-connection exception.
- [ ] `PRODUCT.md` lists the everyday-productivity scope as tasks/work and
      documents, and says what is deliberately out.
- [ ] `PRODUCT.md` states the two measures, and says the product reports on
      itself with them.
- [ ] `PRODUCT.md` states the borrowing rule and points at the protocol
      boundary: conform to ACP, A2A, MCP and the OpenAI-compatible shape;
      never fork one.
- [ ] `PRODUCT.md` states the extension conformance target as a
      _recommendation_, not a decision: MCP Apps (SEP-1865) for agent-created
      UI, AG-UI for the agent-to-UI event stream, with a text-only fallback
      and the host's approval gate kept in front of any agent-initiated call.
- [ ] `PRODUCT.md` states the two rules harvested from the rejected
      directions: one accent with one meaning, and _no ratio whose denominator
      is zero_. A panel that greets its owner with 0% reads as broken, and
      the product's first report on itself must not be a lie by omission.
- [ ] The conformance target is scoped, so nobody reads it as a licence to
      fork something. MCP Apps is the standard for a server shipping its own
      UI to a host, which is a different surface from a domain resource. The
      panel's agent-facing surface is MCP and AG-UI; ACP and A2A are the
      agent-connection side, which we speak when we connect out to an agent.
      Our resources, tasks and goals stay ours, and no protocol is forked.
- [ ] The ADR lists reversibility among the open questions, with the
      reasoning that put it there: with one owner there is no second operator
      to absorb a bad action, so authority without reversibility is exposure.
- [ ] `PRODUCT.md` states the rule that an agent-authored artefact does not
      exist until something has checked it, and points at the ledger as the
      place it is already true.
- [ ] An ADR in `docs/decisions/` — number **0007** — records the session:
      the date, the questions, the owner's answers in their words, and what
      each answer unblocks. It cites the commits it was written against.
- [ ] The ADR names the three findings above, with their sources, as findings
      that sharpen the decisions rather than as decisions taken.
- [ ] The ADR lists what is still open — the extension mechanism, the
      definition of "authored by an agent", and the protocol boundary — and
      says they are being grilled, with the date of the round.
- [ ] The ADR records the licence reality and the one hard case: vendoring
      AGPL-3.0 code into this repository changes this project's licence, and
      that is the owner's decision, not the factory's.
- [ ] The visual direction answer is a _section_ of this ADR, not a second
      ADR. The strategy session and the direction are one session.
- [ ] Nothing under `apps/`, `packages/` or `scripts/` is touched.
- [ ] The documentation matches the code: no sentence claims a capability the
      product cannot produce.
