## Problem

The product's identity was decided on 2026-10-20 in a strategy session with the
owner, and it is not written down anywhere. `PRODUCT.md` still opens with
"Personal OS is an agent-native control panel and personal software factory" —
which is the _factory_ half of the product, not the whole of it.

The owner settled these, and the repo is where a decision lives:

- **Identity.** Personal OS is an environment that one person's agents operate
  and extend. Agents do the work; the owner holds the authority.
- **The human's role.** The owner directs, approves and accepts. Agents do
  everything else. The one exception is connecting a new agent, which is a
  trust decision rather than a decision.
- **Agent-created features.** Typed native resources, authored through
  templates, sharing one resource API.
- **Everyday productivity.** Tasks/work and documents. Not email, not
  calendar.
- **The measure.** The share of shipped features authored by agents inside the
  instance, and the share of routine operations completed without the owner
  touching code.
- **Borrowing.** Other projects are inspiration. We implement against our own
  spec; we do not vendor and we do not depend. Interfaces are conformed to,
  never forked.

## The sweep that sharpened the strategy

Twelve comparators, licences read from the repositories themselves
([`docs/strategy.md`](../../docs/strategy.md), the sweep redone and made
durable). Three findings change what has to be written down. They are
findings, not decisions — the owner has not ratified them.

1. **There is a forming standard for the extension surface, and it carries our
   authority model.** The MCP Apps extension (SEP-1865, proposed 2025-11-21 by
   MCP core maintainers at OpenAI and Anthropic with the MCP-UI creators)
   lets a server ship UI to a host: pre-declared `ui://` templates the host
   can review before execution, communication over plain MCP JSON-RPC so it
   stays auditable, sandboxed iframes, and hosts able to require explicit
   approval for UI-initiated tool calls
   ([post](https://blog.modelcontextprotocol.io/posts/2025-11-21-mcp-apps/)). It
   is a _proposal_, not a ratified standard, and it requires a text-only
   fallback. The host's approval gate is the part that matters to us: it is
   the same shape as "the human decides", and it is the same shape as our own
   ledger. So "native" should mean typed in our contracts _and_ rendered
   through that mechanism, rather than a surface we invent.
2. **Both working precedents of agent self-extension succeed for one reason:**
   a mandatory check before the artefact counts. Anthropic's skill-creator
   authors new skills under a typed contract with evals
   ([skill](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md));
   n8n's MCP server creates real workflows and its own rule is
   validate-before-deploy, copy-before-edit
   ([n8n-mcp](https://github.com/czlonkowski/n8n-mcp)). Our ledger — goal →
   task → execution → evidence → acceptance — is that shape already. The rule
   to write down: _an agent-authored artefact does not exist until something
   has checked it._
3. **The licence reality is why the borrow rule is right.** n8n is Sustainable
   Use, and its licence file says it is "not licensed under any of the main
   open source licenses"; Dify is a modified Apache 2.0 with additional
   conditions. Both are verified in the repositories themselves. A licence can
   change what the product is, which is exactly what the owner's Q5 answer
   refuses. And there is one hard case the owner must decide rather than the
   factory: **vendoring AGPL-3.0 code into this repository changes this
   project's licence.**

reconciled. **Chief counted the routes route by route, independently of

So "twenty of the twenty-nine" should read: _twenty of the thirty-four have a

### DEFECT 2 — `PRODUCT.md:89-90` — "one shared API with the same validation, the same revision handling and the same audit trail"

False on two of the three limbs. The **validation** limb holds.

- **Revision handling.** `PATCH /api/resources/:id` compares `expectedRevision`
  and refuses on mismatch (`modules/resources/service.ts:229-231`). `PATCH
/api/automations/:id` increments `revision` and never compares it
  (`modules/automations/service.ts:113-118`) — last write wins. Chief read
  both and confirms.
- **Audit trail — the same row, two answers.** `PATCH /api/resources/:id`
  writes an entry (`api/resources.ts:55-59`); `PATCH /api/automations/:id`
  writes none (`api/automations.ts:46-50`). Chief confirmed the same
  asymmetry from the route map above.
- **And the worker's own path is invisible.** The automation action
  `resource.refresh` updates the `resources` row directly
  (`apps/worker/src/executor.ts:896-911`): no `revision` bump, no audit
  entry. The worker writes exactly one audit entry in the whole package
  (`executor.ts:97`, the `unknown` transition).

### DEFECT 3 — `PRODUCT.md:44-47` — the external orchestrator

- "retains the external **task id**" — false. The only value ever written to
  `executions.externalRef` is an ACP **session** id (`executor.ts:427-433` ←
  `acp.ts:236-243`). The path for a genuine external task id looks for an
  optional `externalTaskId` adapter method (`executor.ts:1188-1191`) and **no
  adapter implements one** — that path is dead.
- "and **status**" — false. No external status is retained anywhere; the only
  status stored is Personal OS's own.
- "Personal OS **shows** the work, the references and the results" — false.
  `apps/web/src` has zero matches for `externalRef` or `executionOwner`.
- Nothing is ever marked as externally owned: `executionOwner` is only ever
  `'personal-os'` (`conversations/dispatch.ts:143`, `factory/service.ts:221`,
  `:325`), never the contract's `'external'`
  (`packages/contracts/src/factory.ts:40`), and the evidence kind
  `'external-reference'` (`contracts/src/factory.ts:81`) is never written.

### DEFECT 4 — `PRODUCT.md:129-135` — the autonomy policy

- "a way to pause the work" — false. `autonomyPolicySchema`
  (`packages/contracts/src/common.ts:46-54`) carries `mode`,
  `allowedActions`, `approvalRequired`, `maxTurns`, `maxDurationSeconds`,
  `maxSpendUnits`, `dailySpendUnits`. There is no pause. The only pause in
  the product is the conversation's own `paused` flag
  (`db/schema.ts:158-159`), honoured at `routing.ts:77`, `dispatch.ts:105`,
  `executor.ts:199` — a conversation safeguard, not part of any policy.
- "bounded **everywhere it appears**" — false for the workspace and goal
  policy: nothing reads `workspace.autonomyMode`, `workspace.autonomyPolicy`
  or `goal.autonomyPolicy` to make a single decision. The only mention outside
  the storage layer is a display badge
  (`apps/web/src/pages/Settings.tsx:112`). The limits that are actually
  enforced live on the **conversation** (`routing.ts:89-110`), which is a
  different object from the one the policy is attached to.

### DEFECT 5 — `PRODUCT.md:165-166` — "Every resource records who created it"

Two of the six kinds **hardcode** the author:

- automation → `createdBy: 'system'` (`modules/resources/service.ts:170`)
- task → `createdBy: 'system'` (`modules/resources/service.ts:260`)

The `automations` and `tasks` tables have no `createdBy` column at all
(`db/schema.ts:385-401`, `:305-330`). The `resources` table has one
(`db/schema.ts:350-368`), and `tableProvider` writes it honestly from the
caller (`modules/resources/service.ts:128`), which for an agent is the
connection id (`modules/mcp/server.ts:330`). Dashboards, documents, data
sources and memories therefore record their author correctly; automations and
tasks do not.

So the first measure is not merely uncomputed for those two kinds — it is
answered **wrongly**: an agent-created automation or task is recorded as
created by `'system'`.

**This one is not only about the document.** The same false claim sat in two
places that are Chief's own: the Q6 paragraph and the C-20 row in
`.factory/INTAKE.md`, and the premise of [WI-020](WI-020.md) — _"The data is
already there"_. **Chief corrected both.** Fixing `PRODUCT.md` alone would
have left WI-020's premise standing.
