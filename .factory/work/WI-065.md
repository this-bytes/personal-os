## Notes

**Why this is a new item and not WI-030 again.** WI-030 is **done and
accepted** (`e682224`, 08:34:37). Re-opening an accepted item to change its
meaning muddies a record that says what was checked and when. This is a
different change — a revision of a published entry, not the publication of it —
so it takes its own number and its own owner.

**Why the contract's status note is part of the contract and not a comment on
the contract.** The contract leads the code, and that is why WI-030 published
the entry before WI-017 built it. **Leading means something in both
directions**: when the code lands, the contract's statement about the code has
to follow, or the contract is publishing a falsehood about the product it
describes. A client that reads "treat the tool as absent" and obeys is worse
off than a client that reads nothing.

**The migration note is not optional here, and this is why.** Nothing is
reclassified — a template is still not a resource, a resource made from a
template is still an ordinary resource, and no existing client changes what it
sends. **But the surface grew**, and a client that validates `toolGrants`
against a known list will refuse a grant for a tool it has never heard of. The
note has to say that.
