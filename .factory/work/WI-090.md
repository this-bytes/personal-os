# WI-090 — The substrate the product's own two measures stand on

**Owner:** a worker, under Chief
**Verifier:** Probe
**State:** implement — dispatched 2026-10-21 as part of the factory-mechanics phase.
**Numbered:** 2026-10-21 by the session that owns the number space for this push.

## The problem

`PRODUCT.md` §7 makes a headline promise:

> The product answers two questions about itself, and shows both in the panel:
>
> 1. The share of features authored by agents in-instance.
> 2. The share of operations done without the owner touching code.

The route exists (`apps/server/src/api/measures.ts`), the band exists
(`apps/web/src/components/MeasuresBand.tsx`), and **the numbers are wrong** —
not wrong by accident, but because the substrate is not there.

Probe's review of WI-011 corrected the original claim and found the real
defect. The candidate list records it as **C-20**:

> `createdBy` is hardcoded `'system'` for automations and tasks, and **twelve
> of the thirty-four mutating routes write no audit entry at all**.

So `resources.createdBy` — the column that separates an agent's authorship from
the owner's — never says who made the thing. And the audit trail, which is
where "operations done without the owner touching code" comes from, has holes
in it. `PRODUCT.md` §7 itself notes the symptom:

> "the share of features authored by agents" is zero or undefined, because no
> agent has authored a feature in-instance yet.

**It is zero because the column is hardcoded, not because no agent has
authored anything.** A panel that greets its owner with a wrong 0% reads as
broken, and the product's first report on itself must not be a lie by
omission.

## What this item does

Make the two measures computable and correct at the source.

## The scope, stated so it cannot grow

1. **`createdBy` records the real actor.** Every resource write sets it to the
   actor that made the change — the owner, or the agent that acted. Not
   `'system'` as a placeholder. There must be a real distinction the measure
   can count.
2. **The mutating routes write an audit entry.** The twelve that do not, write
   one. Every route that changes something leaves a record of who changed it.
3. **The measure counts what the substrate says.** If the measure's two
   numbers are computed from `createdBy` and the audit log, they are only as
   good as those two. **If a measure cannot be computed, the panel must show
   that, not a number.**

## The rules

1. **Do not change the published measure's shape.** `GET /api/measures` is
   published in `CONTRACTS.md`. Its response shape does not change in this
   item. If the substrate cannot support the published shape, say so in the
   report — that is a contract decision, not one to make here.
2. **Do not touch `CONTRACTS.md`.** It is Wren's file, and a contract change
   needs the owner.
3. **`createdBy` is not a free-text field.** It has to be a closed set the
   measure can count — the existing enum if there is one, otherwise a
   published one — and the actor has to come from the request's authenticated
   identity, not from the body.
4. **Do not backfill history.** Existing rows keep the value they have. This
   item makes new writes correct. Say so in the report, because the first
   measure the panel shows will still count the old rows.
5. **Every change is covered by a test that fails without it.** Not "the
   measure returns a number" — "this route writes an audit entry naming this
   actor", and "this write sets `createdBy` to the agent, not to `'system'`".

## Acceptance criteria

- [ ] `createdBy` is set to the real actor on every resource write, and the
      actor comes from the authenticated identity.
- [ ] Every mutating route in the server writes an audit entry. The report
      names the twelve that did not and shows each one now does.
- [ ] The two measures read from `createdBy` and the audit log, and the panel
      shows a count that follows from the substrate.
- [ ] The published shape of `GET /api/measures` is unchanged.
- [ ] Tests fail without each change and pass with it.
- [ ] `npm run typecheck`, `npm run test`, `npm run format:check` and
      `npm run build` pass.

## Gates

`npm run typecheck` · `npm run test` · `npm run format:check` · `npm run build` ·
`npx tsx scripts/smoke.ts`

## Deliverable

The change, the list of the twelve routes and what each now writes, the tests
and their output, and an honest statement of what the first measure the panel
shows will and will not include.
