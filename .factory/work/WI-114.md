## The finding

**Landing WI-108 moves two code files, and the contract's pointers into them do not
follow.** WI-108 added one helper, `parseSpec`, to
`apps/server/src/modules/resources/service.ts`, and the four providers that answered a
broken spec with `internal_error` and HTTP 500 now answer `validation_failed` and
HTTP 422. The helper's insertion shifts every line below it: **`service.ts` grows from
756 lines to 798 and `templates.ts` from 630 to 642**, and **the eleven citations
`CONTRACTS.md` holds into those two files now point at the wrong lines.**

**The two gates caught it, and the gates are right.** On the tree that carries WI-108's
merge:

- `contractPointers.test.ts` — **5 failures**: `CONTRACTS.md:749`, `:751`, `:759`,
  `:803` and `:822` each cite a line or a range whose first line holds no code.
- `audit-outcome-vocabulary.test.ts` — **1 failure**: `CONTRACTS.md:1230` cites
  `service.ts:594` for "the enqueue of an automation run", and `:594` now reads
  `const automation = db.select()...` — the enqueue is at `:596`.

**Nothing in the code is wrong. The contract is what is wrong, and the contract is
Wren's.** The pointer gate says so itself: *"Correcting a stale citation is a human
decision, and the contract is one file that several items hold at once."*
