## The owner's answer, and the gap it names

**The owner's answer, 2026-10-21: the declaration is checked rather than
asserted.**

The gap: without a test, a new module can appear unclassified and a new table
unclaimed, and nothing says so. The doctrine is explicit that a claim nothing
verifies is a claim.

## Acceptance criteria

- [ ] **Every module under `apps/server/src/modules` is classified**, and the
      test fails on one that is not.
- [ ] **Every table in `apps/server/src/db/schema.ts` is claimed**, and the
      test fails on one that is not — and on a claim for a table that does not
      exist.
- [ ] **No module reaches into another domain's module**, except through
      Substrate, through the shared capability API, or through a crossing that
      is declared with a reason and a work item. The test fails on an
      undeclared crossing.
- [ ] **A declared crossing that no longer exists fails the build**, so the
      list cannot outlive the debt it describes.
- [ ] **The rule is tested as a rule**, not only through the file scan: the
      capability API may read across, Substrate is available to everyone, and
      a domain reaching into another domain is refused.
- [ ] **The test needs no new dependency.** It reads the filesystem and parses
      the imports, and it runs inside the existing `npm run test` gate.
- [ ] **The test proves its own teeth.** A deliberate cross-domain import fails
      the build — the criterion that makes the rest of them mean something.

## Not in scope

- **The manifest.** That is WI-048, and this test checks it.
- **Fixing the crossings that exist.** They are declared, they are owned, and
  WI-059 and WI-060 remove them.
- **Proving that a table is used correctly.** The test proves the boundary and
  the claims, and says so.
