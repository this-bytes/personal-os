## The problem

The repository has a rule about the licences of what it borrows, and the rule
is a **claim in a document**. Nothing checks it. A dependency can arrive with
a licence nobody approved, or a licence that changed under a version bump, and
the pipeline will say nothing.

The owner answered at 08:54 that **the borrow rule becomes a check, not a
claim**. That answer funds this item, and WI-036 funds the ground truth it
compares against.

## Acceptance criteria

- [ ] **A licence change in the lockfile fails the build**, with the
      dependency named and the licence it changed **from and to**. A failure
      that says "a licence changed" is a failure nobody can act on.
- [ ] **An unapproved licence fails the build**, with the dependency named.
- [ ] **The gate compares against the licences WI-036 records.** The recorded
      licences are the ground truth; the gate does not carry a second copy.
- [ ] **A test or check proves that a deliberately changed licence fails.** A
      gate that has never been seen to fail is a gate that cannot fail, which
      is worse than no gate.
- [ ] **The gate's own output is shown in the run**, so a reader of the
      Actions tab can see what it compared and what it found.

## Not in scope

- **The recorded licences themselves.** That is WI-036, and it lands first.
- **This repository's own licence.** The owner's "private for now — no LICENSE
  yet" is about this repository, and it defers neither this item nor
  WI-036.
- **Removing or replacing a dependency.** The gate fails the build; it does
  not fix anything by itself.
- **A licence scanner's findings.** The gate compares the lockfile against
  the record this factory keeps. What the record says is the record's
  problem, and WI-036 owns it.

## Gates

- `npm run format:check`
- The workflow and the root manifest are changed, so the workflow lint in CI
  must pass — and the gate itself must be seen to fail when a licence is
  changed, which is the only proof that it can fail.

## Notes

**Why it is Chief's and not Wren's.** The gate lives in `.github/workflows/`
and in the root `package.json`, which the ownership table gives to Chief. One
want with two owners is two wants, and the want is one thing: a rule that
fails the build.

**Why the proof matters more than the gate.** A gate that has never been seen
to fail is indistinguishable from a gate that cannot fail. The criterion that
requires a deliberately changed licence to fail the build is the one that
keeps this item honest, and it is why the criterion is written the way it is.
