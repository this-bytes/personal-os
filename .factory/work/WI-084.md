## The problem

`PRODUCT.md` §4 names this gap in the product's own words:

> **The third half of that is not built yet: nothing in the product tells an
> agent what a good resource looks like, so an agent creates one from the schema
> alone, and a schema is a type, not an example.**

The owner's settled answer (Q3, 2026-10-20) is already recorded:

> **What "native" means for an agent-created feature — A typed, validated
> resource in our own contracts, authored through templates.**

So the direction is not open. **The shape is.**

The six resource kinds live in `packages/contracts/src/resource.ts`: dashboard,
document, data source, automation, task and memory item. Each kind has a spec
its owning provider validates
(`apps/server/src/modules/resources/service.ts`).

## What this item decides

The design of the template layer — enough that a second agent can implement it
without re-deciding anything.

Cover, at minimum:

1. **Where a template lives.** A typed, versioned registry in
   `packages/contracts/src/` — the single source of truth for every shape that
   crosses a boundary — or somewhere else, with the reason.
2. **What a template carries.** The minimum is the resource kind, the spec it
   produces, and the guidance an agent needs to fill it well. What else, and
   what is deliberately *not* in a template.
3. **How an agent gets one.** Over MCP, which is the panel's agent-facing
   surface. Which tools: a template that can be listed, read, and instantiated.
   A tool that is not granted is not published at all — so the template
   surface has to be grantable per connection.
4. **How instantiation works.** A template instance is a resource, validated by
   the same provider that validates any resource. It gets a revision, it
   appears in the audit trail, and it is authored by whoever instantiated it —
   so the product's own measure of "features authored by agents" counts it.
5. **How templates get better.** Templates are versioned and a template change
   does not rewrite the resources already made from it. What happens to an
   existing resource when its template is revised.
6. **The first six.** One template per resource kind, and the guide text that
   goes with each. The guide is the part that closes the gap — the thing that
   makes a good dashboard a good dashboard.
