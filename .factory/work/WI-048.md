# WI-048 — The domains, in a form a test can check

**Owner:** Cog
**Verifier:** Probe
**State:** verify — the manifest is written; Probe checks it against the modules
and the schema.
**Opened:** 2026-10-21 by the strategy session, from the owner's decision on the
domain structure
**Numbered:** 2026-10-21 — WI-046 through WI-061, taken by the session that owns
the number space.

## The owner's answer, and the gap it names

**The owner's answer, 2026-10-21: five domains, declared before they are moved,
and the declaration is checked rather than asserted.**

The gap: a map that exists only in a document lasts about one sprint, and this
repository already names "a claim that nothing verifies" as a weakness (C-13).
The map has to be machine-readable, or it is a claim.

## Acceptance criteria

- [ ] **`apps/server/src/domains.ts` classifies every module** under
      `apps/server/src/modules` into exactly one domain, and every table in
      `apps/server/src/db/schema.ts` is claimed by exactly one domain.
- [ ] **The rule is a function, not prose.** `isAllowedImport` says what is
      allowed: the same domain, anything in Substrate, the shared capability
      API reading across, and a declared crossing. Everything else is refused.
- [ ] **Every crossing that exists today is declared**, with a reason and the
      work item that removes it. A declared crossing is a debt with a name, not
      a permission.
- [ ] **A table written by a domain that does not own it is declared too** — as
      a shared table write, with the reason and the work item that removes it.
      These are declared rather than enforced, and the file says so: proving
      that a module writes only its own tables needs a data-flow analysis this
      repository does not have, and a rule nothing verifies is a claim.
- [ ] **No dependency is added.** The manifest is plain TypeScript in the
      server package.
- [ ] **`npm run typecheck` and `npm run test` pass.**

## Not in scope

- **The test.** That is WI-049.
- **The human copy.** That is WI-047.
- **Moving modules.** The manifest classifies what is there; it does not
  reorganise it.

## Notes

Two crossings exist today, and both are the implementation's, not the map's:

- Resources → Work, in `modules/resources/service.ts`, where the task resource
  provider reads the ledger. WI-059 removes it.
- Interaction → Work, in `modules/executions/service.ts`, where resolving a turn
  writes the ledger's row. WI-060 removes it.

The second one is a table write rather than an import, which is why the
manifest keeps it in a separate list.
